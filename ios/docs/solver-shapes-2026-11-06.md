# 形狀搜尋本機模擬：重複補搜與候選剪枝

2026-11-06，使用者要求根據五色失敗情況模擬其他形狀，並明確授權「執行本機模擬（不打包、不啟動 CI）」。產品來源為 `084f2c7`，本輪沒有修改產品求路器。新增可重跑的研究工具、匿名構造盤面和結果；沒有操作裝置、派發 CI 或改動 `E:/ipa`。

環境：Windows、AMD Ryzen 9 9900X（12 核／24 執行緒）、MSYS2 GCC 15.2.0、C++17／`-O2 -Wall -Wextra -Werror`。未關閉測試斷言。時間受主機排程影響；不得換算成 iPhone 耗時。主要 828 盤重跑期間有部分診斷批次重疊，不能將數毫秒差異解讀成性能改善；所有上述失敗都未逾時，且完成搜尋量與路徑可重現。

828 盤包括單一 L／十字／T／3×3 正方形／四連各 36 盤，以及雙 L／雙十字／雙 T／雙四連／雙橫排／雙直排／T＋四連／正方形＋四連／L＋十字各 72 盤。每組包含原盤、180 度旋轉及全色號循環映射；T／正方形配四連的原盤與旋轉版為心色，換色版為其他顏色四連。這些變體互相關聯，不能視為 828 個獨立實戰樣本。

先建立達標形狀，沿合法連續路徑打亂，再保存反向路徑作存在解證據。該路徑只交給獨立重播檢查，**不交給求路器**。背景與多餘同色珠均有變化；生成後的盤面未排除本來已達標的簡單情況，所以全過不證明任意盤面都可解。原始盤面與證據已完整保存，後續不依賴亂數函式庫重建。

## 已確認的不足

### 1. 普通單條形狀目標的 recovery 可以原路重跑

在無轉轉、只有一條形狀目標時，`stableHints=false` 不改提示；聚焦第 0 個目標只把同一進度乘上固定倍數。這可能保留完全相同的排序，與五色失敗的「只增加時間」有相似問題。

關閉 backtrack 比較 recovery 0／1，目標與步數相同：

| 案例 | 一次搜尋 evaluated | 開 recovery evaluated | 所選失敗路徑 |
|---|---:|---:|---|
| `Square-03-v0` | 11,173 | 22,346 | 完全相同 |
| `DoubleT-09-v1` | 14,886 | 29,772 | 完全相同 |

下一步應讓補搜採用不同的布局／供珠策略，或略過已知等價的重跑。單純把 Session 時限增加到 2000 ms 不能解決這個內部重複。

### 2. 窄 beam 丟掉關鍵布局，旋轉後也可能改變成敗

| 失敗組 | 128／120 的失敗數 | 失敗耗時 | 缺少目標 |
|---|---:|---:|---|
| `Square-03` 原盤／旋轉／換色 | 3 | 26–32 ms | 正方形 |
| `DoubleT-09-v1` | 1 | 46 ms | 第二個 T |
| `LCross-10` 原盤／旋轉／換色 | 3 | 53–54 ms | 十字 |

七盤皆已搜尋至 48 層、4 個 pass、2 次 backtrack，仍保留安全但不達標的候選，獨立 oracle 確認沒有誤報成功。延長時間後 evaluated 與候選路徑逐一相同；因此這批失敗不是時間截斷。雙 T 的原盤與換色版可解，180 度旋轉版失敗，反映方向與同分排序對有限候選的影響。

目前只能確認剪枝敏感，不能把所有漏解歸因於下述某一個評分公式。應保留這七個案例，對多樣性與補搜方向做對照；不能以放寬形狀、放寬首消或放寬安全條件換取「成功」。

### 3. 同色雙形狀的提示可能偏向互相衝突的高分布局

研究工具直接觀察 production hint，對最多六個提示比較「逐個挑最高分」與「最佳相容組合」，再比較保留全部模板的研究上界。這是**提示評分診斷，不是可達路徑／不可解證明**。

| 同色 count=2 | 沒有現成命中的樣本 | 貪心低於六提示最佳組合 | 前六提示漏掉更佳相容組合 |
|---|---:|---:|---:|
| L | 288 | 72 | 139 |
| T | 288 | 51 | 144 |
| 十字 | 300 | 89 | 53 |
| 四連 | 290 | 60 | 54 |
| 橫排 | 300 | 17 | 0 |
| 直排 | 297 | 16 | 0 |

例如 L 的固定盤面 `350030013344540202021042110505`，逐個挑選得到 1706，但相同六個提示中有相容組合合計 2986。兩類數量可以重疊，不能相加當失敗比例。樣本取 300 個固定 seed，排除已有該形狀命中的盤面；其本身不一定有合法連續拖曳解。沒有用 6×5 的雙正方形資料推論效果，因為兩個隔離 3×3 正方形無法如此放置。

已在**暫存求路器副本**試驗最多 64 個子集的最佳相容組合，跑相同 648 盤窄 beam：仍為 644／648，四個漏解未改善。沒有把此變更寫入產品來源。這說明只修局部貪心不足以解決已觀察到的漏解，還須研究前六個提示的布局覆蓋及搜尋方向；目前沒有證據支持直接擴大所有提示池。

## 核對方式與限制

- 獨立 oracle 逐行掃描消除、連接實際標記的同色群組，再重建各列重力；不呼叫 production 的 evaluator／replay。L／T／十字／正方形／四連按首批實際消除群組判定，未消除鄰珠不自動使形狀失效。橫排／直排按實際寬高，較大群組可包含完整排。
- 所有已保存解及 solver 回傳路徑均檢查相鄰交換、步數、實際形狀數、Combo／消除數；固定起點批次另外檢查首格。沒有隨機天降，也沒有把成功 witness 當搜尋種子。
- 模擬主要是 6×5／7×6、普通無轉轉、無荊棘／毒／封條盤。未在此壓力資料集涵蓋首消限定直排側枝、所有尺寸、多人時窗或特殊消除門檻。既有整套本機回歸涵蓋另一些案例，仍不能替代手機／macOS Session 驗證。
- 本輪 Windows model／solver 整套回歸通過。上次五色原盤／換色／鏡像均為 5／5，40／38／43 步，173／160／179 ms，兩個 pass、零 backtrack、未逾時。這是 `084f2c7` 共用 C/C++ 的新本機證據，**不驗證上次修改的 Objective-C++ Session**。

完整本機回歸使用 `ios/tools/windows-tests.sh`，本次 `BUILD_DIR=build/shape-simulation/regression`。在同一來源重建 probe 時，以 GCC 先產生 `PHOrbModel.o`、`PHBattleModel.o`、`PHInputModel.o`，G++ 產生 `PHOrbSolver.o`，再以 C++17／O2／warnings-as-errors 連結 probe。不要沿用來源已不同的舊 object。

```text
python ios/research/orb_shape_simulation.py --probe <本機probe.exe> --source-commit <實際建置commit> --output <新結果.json>
```

窄 beam 加 `--beam 128 --budget 120`；指定七盤用 `--ids Square-03-v0,Square-03-v1,Square-03-v2,DoubleT-09-v1,LCross-10-v0,LCross-10-v1,LCross-10-v2`。可加 `--diagonal`、`--fixed-start` 或 `--recovery 0 --backtracks 0` 作隔離對照。縮短 `--steps` 前必須選出 witness 本來就在該步數內的資料，工具會拒絕超出步數的存在解證據。工具拒絕覆寫既有結果，保存 dataset／probe hash；`--source-commit` 是呼叫者提供的來源標籤，不是二進位來源證明。

完整原始輸出留在 `build/shape-simulation/`；版本控制內保存可重跑的匿名資料、代表路徑與摘要。本次僅完成本機研究，沒有新 dylib／APK。
