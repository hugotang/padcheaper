# 武裝無效時補 L

2026-11-01，源碼與回歸案例已接入，**尚未編譯、執行案例、測量效能或製作新版 dylib**。0.5.14／CI 87 不包含本批。

這是 [敵方行動與技能排程設計](enemy-aware-automation.md) 的第二步：普通單人連續模式可開啟 `assistRecoveryL`，在武裝無效期間保留全部原有盤面條件，補上預測足以解除剩餘回合的有效 L。它不判斷下一擊能否存活，也不改變必要救援技能。撤下光 T、只排 L＋心四耐久一回合仍未實作。

## 設定及使用範圍

詳細轉珠頁新增「武裝無效時補 L」。新設定、缺少此鍵的舊設定及一般策略預設 `false`，只接受 JSON Boolean。修改會與已選策略一起原子儲存；失敗保留舊值。雨龍兩份整包及手動開場後策略庫預先設為 `true`，需要支援本批的新版建置後重新匯入；不會改寫既有保存策略。CIEL 範本維持原有設定。

只有使用者明確開始的普通單人連續模式套用此政策。手動預覽、明確「轉一次」、3／4／8 人及 3 人單人續玩都不增加這套資料依賴或自動操作權限。關閉政策時仍走既有求路和技能檢查。

## 判定與執行

1. 在穩定的單人操作階段讀取目前武裝無效的有號十位回合數、關卡規則，以及六格當下有效 L 覺醒、潛覺 48、主／副／第三屬性。L+ 108 算兩個 L；同一隊員的重複屬性對同一組消除只算一次。不同有效隊員、不同消除組可以累加。
2. 必要技能、開場和救援仍先按原規則完成。最後求路前重新讀取，不沿用技能前盤面，也不採用每 0.75 秒更新的 `battleObservation` 診斷快取。
3. 以每色最低保證珠數枚舉足量 L 組數。既有同色 L 直接沿用；光 T＋光 L 至少要 10 光，既有心四／心 L 等形狀也保留自己的珠數。同色 T／L 另做必要分隔空間檢查。全部共享轉轉相位都要符合。
4. 保留最少新增組數的候選，最多搜尋 12 份配置，共用原 fast／balanced／thorough 的一次時間預算；可先試另一個有效屬性。最後用實際選中的目標重新重播和校驗。搜尋未找到路徑不等同盤面無解，不放寬目標或自動反覆重試。
5. 等待求路／預覽時最多每 0.25 秒重查證據；執行前與持珠中重查，原生座標轉換後、第一次寫入前再核對。回合、提供隊員、有效覺醒、屬性、武裝來源或回合數改變就停止；已持有的珠子保留原有放手機制。
6. 完成路徑後等待實際消除、敵人行動與下一個穩定操作階段。只有重新讀到同一場次的武裝無效為 0 才繼續；殘留、再次施加、未知資料或逾時均停止。解除後重新判斷隊伍、技能和原有目標，不繼續帶上臨時 L。

綁定、封覺醒、關卡禁止覺醒／潛覺、沒有潛覺或有效 L 都不能提供回復量。暫時停用的武裝覺醒不先算回來。動態 L 授予、未支援武裝變體或損壞資料標為未知；若其他已核對隊員仍能提供足量，可使用其保守已知部分。關卡直接禁止武裝與無法形成 L 的最少消珠規則不適用。

整包隊伍核對可辨認「來源仍是原武裝、受保護狀態低位為 172、當前生效武裝因正回合無效而為 0」。需要本次新讀取的證據和精確來源一致；不把缺少武裝當成已消耗武裝，也不改寫原生狀態。暫時變身仍按原有身份核對；無法分辨的混合情況停止。

## 證據及限制

日服 iOS 23.6.0 的靜態原生鏈為 `1005F7954` 的五格 L 判定、`1005FC5CC` 的每組旗標、`100601ED0`／`10060594C` 的屬性攻擊項目，以及 `1005AC4C8` 的潛覺與回合數消耗。原生列座標由下往上，既有四方向 L 均可在所有放得下的邊緣成立，沒有額外方向排除。solver 的同色邊界限制仍比原生保守。

新增 45 組 64-byte 政策指紋，與既有 114 組操作指紋、15 組診斷指紋分開。只有明確開啟此政策才要求新指紋；現有操作 gate 不被擴大。資料收集只呼叫安全讀取和純解碼 helper，沒有 native getter、技能施放、CD 快取初始化或 guest 寫入。

兩次收集會比對機制值、來源表、key、入場識別、操作階段、wave、moves 與持珠指標；這是有界前後一致性檢查，不能提供跨執行緒原子快照或排除所有 ABA 變化。

原生攻擊佇列容量為 256；目前只接受操作前 head／count 均為 0，並拒絕另一路特殊 dispatch `525190`。已確認還會產生非攻擊項目，**尚未證明所有消除、天降及附加效果的完整容量上界**。因此 L 回復量是目前條件下的預測，不能用來保證本回合恢復裝備或存活；實際不足會在下一穩定回合停止。也不提前計入裝備恢復後增加的覺醒數。

`assistRecoveryTrace` 保存各色量、提供隊員、阻擋原因、候選、實際確認結果；`searchTrace` 另有各候選預算與總耗時。`actualConfirmed` 只表示後續讀到回合數為 0；普通回合扣減、敵人再次施加和其他原生效果未被分離，`lOnlyAmountConfirmed=false`。不宣稱回血、盾、下一擊、下一回合 CD 或存活已知。iPhone 的新增讀取成本及長路徑幀率仍待測。
