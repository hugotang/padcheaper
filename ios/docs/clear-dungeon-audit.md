# 通關回傳與狀態一致性：23.6.0

2026-10-30，唯讀分析原始 PAD JP 23.6.0／106878，UUID `DD332AD4-4C92-3AAF-85D0-3892556A3A0E`，executable SHA-256 `611c93f5472fceddfa27254b718c6eff1decdc6814cc927e2faa4c7c250a65ec`。沒有發送遊戲 API、改寫 clear_dungeon、清除 audit 或偽造廣告／續關成功。

**通關並非只回傳最後隊伍或 HP。** builder 讀取戰鬥過程統計、計時、持久化隊伍徽章檢查及累積一致性旗標。通關前換回隊伍不能撤回這些已發生的紀錄。客戶端程式無法揭示伺服器全部驗證規則，也無法量化本模組被偵測的機率。

## 請求結構

`0x1006921C8` 呼叫 `0x100691748` 解碼靜態字串，結果為：

```text
clear_dungeon&pid=%d&sid=%s&hash=%s&tmd=%d&nxc=%8x&dung=%d&floor=%d&v=2&c=%d%s&tskip=%d
```

此處列的是格式，不含任何玩家的實際值。body 先建立 `ss`、`s`、`e1..e36`、可選 `pb`、`sm`、`cm`，再由 `0x10058F788` 編碼為 HTTP body 的 `e=...`。

`ss` 取整數 `CFAbsoluteTimeGetCurrent()`，不是 Unix timestamp；`s` 取自 `S+0x5CA104` 的編碼狀態，完整語意未確認。`e` 各欄還有逐欄混淆，`sm` 累積這些值的校驗，`cm` 與模式分支相關。`nxc` 也組入 audit 狀態，因此不能說一致性結果只存在 e14。

以下 `S` 指 save object `0x101B517B0`；欄位來源指混淆前、經原生解碼的值。IDA 把部分 save offset 顯示成 `loc_1005CA...` 並不表示那是實際資料位址。

## 戰鬥期間的一致性檢查

`0x1005B4BF4` 比對 HP 及其 shadow、敵方數值對照、其他 protected 戰鬥量、隊伍摘要及統計校驗。異常以 OR 累加到 `S+0x5CA0BC`，正常分支沒有相應地清掉先前旗標。`0x1005A8010` 在特定 timer flags 下比較 native 計時與 CFAbsoluteTime 差異，差距達門檻時也累加旗標。

這支持「臨時改值再還原不能當作未發生」，但不能由函式存在推斷某一次 log 一定被處置。完整隊伍摘要、統計值或合法外觀選擇是否觸發伺服器何種判斷，仍缺服務端證據。

## 對目前功能的含意

| 功能 | 已知範圍 |
|---|---|
| 隊伍／HP／技能資料替換 | 不只影響畫面；會進入原生數值／摘要與操作統計。使用原生 setter 及刷新可減少本機狀態錯誤，不能當作與正常隊伍完全等價或不可偵測。 |
| 自動轉珠 | 目前走原生輸入，仍會產生正常換格及位置相關統計。沒有證據證明伺服器是否用這些資料判斷自動操作；本版沒有加入隨機軌跡來掩飾。 |
| 徽章／BGM 保存 | `save_decks` 預設化只涵蓋該 action；e18 另會檢查持久化徽章。保存 bug 修好不代表其他 action 或整場戰鬥只看到預設值。 |
| 未通關 BGM | 新功能使用暫時音樂 override，通關表唯讀，未新增解鎖通關／獎勵／計時或 payload 寫入。沒有因此宣稱整個已注入客戶端等價官方環境。 |
| 計時修正 | 計时存在獨立累積／一致性欄位；不能承諾關閉／還原 flags 可撤回先前差異。 |
| 廣告／魔法石復活 | 原生有 `adv_reward → do_continue → do_continue_ack`，本機補 HP 不等於正式續關。詳見 [廣告復活](ad-revival.md)。 |

本次可落實的是修正錯誤保存、確保原生操作結果已確認、避免對不明狀態繼續寫入，並保持 `clear_dungeon` 原樣傳出。沒有可驗證的「降低封號機率百分比」或免偵測保證；要降低與官方狀態的差異，應減少戰鬥參數替換，使用自己原生隊伍，並把無法確認的操作停下來。
