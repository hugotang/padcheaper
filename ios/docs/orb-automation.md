# 單人連續轉珠與技能規則

`0.5.2-orbs` 的連續轉珠與技能規則。使用者可自行設定觸發條件；編譯及自動測試結果見 [驗證記錄](development.md)，原生技能效果仍需真機核對。

0.5.3 的 [盤面效果批次](orb-effects.md) 納入集中驗證，最新結果見開發紀錄。它增加各種妨礙條件、轉轉共用相位穩定與缺珠範圍判斷；舊 0.5.2 遇到轉轉仍停止，夜一自動規則先停用。

## 操作

新版建置完成後，進入目前要操作的單人關卡，開啟功能總開關，在 PC →「自動轉珠 · 連續／技能規則」設定求路品質、盤面目標與技能規則，再按「開始連續轉珠」。每回合先處理技能，再求路及轉珠。保留「讀盤並求路／執行一次」供核對盤面。

「停止」固定在頁面底部；返回遊戲後，浮動按鈕在求路、施放技能及等待下一回合時都會顯示「停止自動」。觸碰遊戲、離開前景、關閉總開關、切換帳號、進入多人或離開本場戰鬥都會取消連續模式。已啟動的技能仍由遊戲完成，停止不退回已消耗的技能。

每次開始只綁定目前的單人戰鬥。啟動狀態不寫入設定，也不自動選關、進入下一場、續關、點擊掉落或結算畫面。

## 規則

最多 12 條，依顯示的優先順序判斷。同一條中的條件全部成立才嘗試技能。每個位置每個轉珠回合最多施放一次；重複規則不能讓同一位置再次施放。一般規則在冷卻未完成、封技或原生判定不可用時略過並記錄原因；必要規則會在其他候選處理完後核對，仍需施放但未確認完成時停止轉珠。放完其他技能後會重新檢查先前未冷卻的規則，因此可接續處理加速技能。

0.5.5 在「有不可消效果」下增加火／水／木／光／暗／心複選；任一所選珠色不可消便符合，不選表示任意珠色。儲存欄位 `unmatchableColors` 是六位遮罩，0 為舊行為，光為 8、心為 32、光或心為 40；只能搭配 `obstacle=unmatchable`，資料未知時不猜測。

要設「暫時覺醒無效或光不可消」，建立兩條同位置、獨立施放規則，分別只設暫時覺醒無效與光不可消。兩條實現 OR，同位置本回合仍最多一次；同一條同時選兩種條件代表 AND。

後續源碼已加入輪替組、本場一次、位置保留樓層、妨礙盤面條件與最多 64 份隊伍／關卡策略。輪替組同回合只選一個技能；各組的優先度由最上方成員決定。新增欄位與配對方式見 [策略說明](orb-strategies.md)，舊規則保持相同行為。

第五批再加入有效 HP 百分比、暫時覺醒無效／隊員綁定／技能封印條件、必要技能及逐條判斷原因，詳見 [HP 自救與必要技能](orb-survival.md)。這些欄位都是可選，舊規則不會自動變成必要規則。

| 欄位 | 含義 |
|---|---|
| 位置 | 1 隊長、2–5 隊員、6 助人 |
| 角色圖鑑編號 | 0 只限定位置；非零還需符合當前角色形態的圖鑑編號 |
| 回合間隔 | 1 每回合；2 為本次開始後第 1、3、5…回合；範圍 1–999 |
| 技能就緒就放 | 快捷設為間隔 1；每次轉珠前確認可用，保留所有其他條件 |
| 指定樓層 | 0 所有樓層；1–999 對應遊戲的第幾層 |
| 缺珠 | 指定六種基本珠之一；盤面珠數嚴格少於指定數（1–43）才觸發 |
| 敵人效果 | 傷害吸收、屬性吸收、傷害無效或 Combo 吸收；至少一名存活敵人有該效果 |

敵人效果條件會略過已由我方全隊技能無效化的效果，延遲到下回合才生效的無效化不算已生效。這裡不計算個別角色覺醒、傷害門檻、屬性或是否能擊殺敵人；角色與對應技能由使用者指定。

未建置批次中，轉轉盤面的缺珠條件使用全部共用相位的珠數範圍。最大值仍低於門檻才觸發；最小值已足夠便略過；若跨越門檻則回報無法確認並停止。技能準備到原生呼叫前再核對盤面及觸發條件，技能造出／移除效果後重新求路。

兩個 2 回合技能要每回合輪流施放，兩條都設同一「輪替組」及間隔 1，關閉「本場一次」，按要使用的先後順序排列。輪替組每個轉珠回合只用一個，原生確認啟動後游標移到下一條；未就緒者可略過。冷卻由遊戲判斷，間隔 2 會把兩條都限制在本次第 1、3、5…回合。白哉位置 5、6 的範例見 [0.5.2 設定說明](release-0.5.2.md)。

技能使用該位置當前可用的原生技能，包含已蓄好的繼承。不指定本體／繼承選擇、不自動回答技能選項，也不替使用者判斷整隊最佳技能。需要額外選擇的技能若無法自然完成會逾時停止。

0.5.4 的[技能修正與診斷](orb-skill-selection.md)將待命殘留選擇與開啟中的選擇框分開處理。前者通過原生可用性及狀態校驗後還原預設選擇再施放，後者繼續等待或停止。拒絕訊息保留當次充能、實際本體／武裝技能 ID、CD 及階段，區分冷卻不足與冷卻已足但遊戲拒絕；面板標明規則和位置。同回合每位置一次限制保留，下一回合重新檢查就緒狀態。這些變更不包含在已交付 0.5.3，最新建置狀態見 [開發紀錄](development.md)。

規則只在「儲存規則」寫入成功且收到設定回讀確認後生效；失敗保留草稿與錯誤。規則輸入頁暫時取得鍵盤焦點，關閉後返回遊戲視窗。留空規則會只連續轉珠。連續模式中不能修改品質、目標或規則；外部修改會留待本次停止後載入。

範例：第 3 層、缺心珠時用位置 2 的技能；敵人有傷害吸收時用位置 4 的技能。

```json
{
  "orbs": {
    "quality": "balanced",
    "mode": "combo",
    "goals": [],
    "rules": [
      {"enabled": true, "slot": 2, "monster": 0, "every": 1, "floor": 3,
       "color": 5, "below": 3, "enemy": "none"},
      {"enabled": true, "slot": 4, "monster": 0, "every": 1, "floor": 0,
       "color": -1, "below": 0, "enemy": "damage_absorb"}
    ]
  }
}
```

舊 config 缺少 `rules` 時等同空陣列。`color` -1 表示不限定盤面，此時 `below` 必須為 0；其餘值 0–5 分別為火、水、木、光、暗、心。每條規則需包含範例中全部欄位，拒絕未知欄位、數字代替布林、溢位與小數。

## 執行與停止邊界

流程為「穩定快照 → 依規則嘗試一個技能 → 等待原生完成 → 重新讀取 → 下一個技能或求路 → 確認每步交換及放開 → 等待消除與下一回合」。技能和拖珠不會同時排入原生 frame。

穩定快照需至少相隔 0.20 秒，並符合相同盤面、隊員、技能次數與敵人效果。未建置效果批次允許已建模轉轉的共用色序推進，token／限制與其他資料仍須一致；未支援轉轉只能以完全一致快照嘗試指定補救技能。原生技能啟動前再次核對；原生可用性檢查後也重新讀取，才進入原生確認施放入口。可用性檢查會更新遊戲的技能階段及繼承選擇快取，因此不能當作輪詢 getter；一般快照只讀記憶體。

技能以原生 phase 22／隊員 state 2 確認啟動，再以原生技能使用計數的增加，以及恢復穩定可操作狀態確認完成。已看到的計數增加會保留，避免技能清場切層後計數重設遺失確認。未確認啟動／完成不重試該技能。

只在本次轉珠已明確放開、觀察到消除／攻擊 phase 3–6，再恢復 phase 2 且原生交換計數歸零、盤面穩定時，才增加連續回合並清除當回合施放紀錄。技能的 phase 22、彈窗或任意非操作階段都不能單獨當成新回合。技能清場切層也不重設本輪已施放的位置。

初始可操作狀態等候最多 12 秒，技能最多 30 秒，轉珠後等候下一回合最多 90 秒。超時、記憶體讀取失敗、目標未達成、操作時間不足或資料改變會停止並保留訊息；不在無法確認的狀態反覆嘗試。

技能可先處理某些不能轉珠的盤面，例如改掉毒珠或解除不可消；技能後重新依當前支援範圍求路。新批次只有在全部目標及毒／爆彈條件成立時才開放輸入，未知珠型、旗標與特殊規則仍停止。敵人部位尚未建模，不能用它們判斷敵人效果或啟動技能。多人限制不可由規則覆蓋。

## 23.6.0 靜態依據

目標仍是 PAD JP 23.6.0／106878，原始 Mach-O base `0x100000000`；與 [自動轉珠](auto-orbs.md) 使用同一 UUID／原檔 SHA256。下面是 IDA 的靜態對照，尚非真機呼叫成功紀錄。新增入口、技能流程及敵人傷害函式的 64-byte 指紋保存在 `ios/targets/orbs-23.6.0.json`。

| 位址／欄位 | 依據與用途 |
|---|---|
| `0x1005AFA74` | 原生隊員點擊；存活敵人、敵人行動、綁定、封技、特殊動畫與其他前置條件 |
| `0x1005C38B8`／`0x1005C4070` | 原生 readiness 與 can-use；檢查充能、關卡限制、技能是否可生效，selector -1 選當前技能 |
| `0x1005CC374` | 原生確認施放入口；設定隊員 state 2、phase 22、動畫並由後續流程執行效果 |
| `0x1005CC198`／`0x1005CBFE8` | 原生入口準備技能演出，更新當前技能 ID；不自行設定該 ID |
| `0x1005CCE18`／`0x1005CB714` | 技能處理與結束；由遊戲處理充能、變身、複合／進化技能及效果 |
| `impl +741448` | 受保護 unsigned 16-bit 技能使用計數，`5CB714` 每次最外層技能增加，飽和到 255 |
| `0x1005B4EDC` | phase 1 初始化操作回合並重設 `impl +601668`；phase 3–6 為轉珠結算，22 為技能 |
| `impl +725488 +1520×slot` | 六個隊員；+72 綁定、+456 充能、+1220 override、+1224 技能 state、+1248 CardParam、+1292 catalog ID |
| `impl +777344` | 受保護敵人數，最多 8 |
| `impl +753464 +2984×index` | 敵人；+532 flags，+64／+80 為保護 HP 低／高 32-bit，+23 是點擊技能路徑的行動 gate |
| `0x100562F74` | 傷害判斷中實際消費下列敵人效果與我方無效化欄位 |
| 敵人 +2400／+2192／+2256／+2224 | 傷害吸收／屬性吸收／傷害無效／Combo 吸收的受保護剩餘回合；屬性 mask +2176／+2240 |
| impl +739196／+739156／+739668／+739176 | 對應我方無效化效果；相鄰 +2 欄位為延遲，均按 signed 10-bit duration 判斷 |
| `0x1005EC430` | 教學步驟查詢；75 在原生點擊路徑限制隊長，此版不於該步驟自動施放 |

所有受保護值採三份解碼一致，並核對充能 shadow、catalog 指標、場景、帳號 epoch、entry hash、單人 selectors 與原生程式指紋。只呼叫原生 can-use 與確認施放入口，未直接呼叫效果 dispatcher，也不自行寫入冷卻或敵人 HP。

## 自動測試範圍

- `orb_rules_tests.m`：條件交集、嚴格缺珠門檻、樓層／間隔、敵人效果／我方無效化、讀取未知及 JSON 型別。
- `orb_automation_session_tests.inc`：一鍵跨回合、技能先於拖珠、同回合防重複、加速後重評估、改盤／清場後重讀、技能確認／超時、背景／手動／多人／帳號／讀取失敗、取消後的舊 solver 結果。
- `orb_skill_native_tests.inc`：純讀取、原生 can-use／start 替身、tap gates、技能計數飽和、指紋與充能校驗、存活敵人、延遲無效化、敵人部位、技能補救不放寬拖珠 gate。
- 設定與 GUI probe：規則保存相容性、保存失敗保留草稿、數字鍵盤與遊戲焦點還原、開始未確認時保留頁面、各自動階段的固定／浮動停止控制。

集中編譯測試後，仍需真機核對原生技能入口、繼承、複合／進化／變身、敵人效果、低 frame rate 下的讀取負擔、多樓層與最終結算。不能用舊版的單次轉珠回報替代這些驗證。
