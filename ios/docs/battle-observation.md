2026-11-01，源碼已接入第一階段診斷，**尚未編譯或執行測試**。0.5.14／CI 87 不包含本批。這是 [敵方行動與技能排程設計](enemy-aware-automation.md) 的觀測基礎；完整敵人行動圖、下一擊傷害、回血／減傷及 L＋心四連耐久決策仍待實作。

- 目前普通敵人的存活數、64-bit HP，以及傷害吸收／屬性吸收／傷害無效／Combo 吸收的各自持續回合與遮罩。部位等未支援資料標記未知。這不是敵人的下一招、攻擊倒數或傷害預測。
- 我方已校驗 HP／上限，暫時武裝無效剩餘回合及 fresh 標記。關卡禁止武裝、暫時變身、來源武裝、目前生效武裝、已消耗／移除狀態分開保留；不從顯示上的「沒有武裝」反推單一原因。
- 六格目前技能 ID、正式／快取進化階段、本體及武裝 CD、目前充能、距本體／武裝門檻的充能差。來源家族相同只是一項原生選擇資格，不表示本體可以立即施放。
- 解武裝潛覺 48、有效 L 覺醒 60／L+ 108（計兩個）、隊員當前主／副／第三屬性。綁定、封覺醒、關卡禁止覺醒／潛覺會阻止資格。缺少潛覺或 L 時明確不可用；動態追加 L 覺醒的條件尚未完整建模，標記未知。

L 資格來自當下參數、解鎖覺醒、有效武裝、超覺醒／同步覺醒及受保護的追加覺醒欄位，不沿用編成預設。武裝的裝備覺醒必須位於已解鎖範圍。顏色去重，心珠不當成攻擊屬性。這批**尚不把 L 覺醒數直接宣稱為實際解除回合數**；要先核對攻擊項目生成、消除輪次、同色多 L 與結算順序，再接臨時盤面目標。

## CD 的讀取界線

原生 `0x10059FAE4` 會在關卡 CD 修正快取未初始化時解析並寫入快取，因此診斷不呼叫它，也不呼叫 can-use 或技能選擇函式。只讀技能表與三份一致的已初始化 CD 修正；負值／損壞／不支援武裝變體均回報未知。

普通技能 CD 使用 `base + (min(maxLevel, level) - 1) × signedDelta`。技能表 +18 是每級有號 CD 差，原本 `cachedCooldown` 欄位命名已更正為 `levelCooldownDelta`。武裝技能等級依原生為單一 byte，不讀旁邊 byte 作高位。

type 232 進化後用對應子技能 base CD，超出階段停在最後一段。type 233 到循環末端後使用根技能 CD 與第一個子技能 ID。初始階段使用根技能的等級公式。診斷依受保護正式階段計算，另外列出原生快取階段差異；不寫回快取。

已初始化的關卡 CD 修正：本體非零 CD 加一次，存在生效武裝時非零合計加兩次。負數、溢位或表索引錯誤回報未知。充能達門檻仍可能因封技、盤面條件、來源選擇等被遊戲拒絕；充能差不代表幾個回合後必然可用，加速／延遲／進化均可能改變它。

## 取樣、可見性與隔離

沿用轉珠功能的監看生命週期；未使用轉珠功能不新增輪詢。穩定普通單人盤面約每 0.75 秒最多取樣一次；讀取時以兩次收集核對來源表、受保護 key、入場識別、我方狀態、敵人／L／CD 觀察值、phase／wave／moves 及持珠指標。這是有界唯讀核對，不是原生原子快照。

技能動畫、改盤、持珠、執行中的手勢、多人、背景或讀取失敗時撤下資料。新場／wave／盤面／技能狀態改變立即隱藏舊證據，到下一個取樣時間才重新讀取；撤下資料不重設 0.75 秒間隔，避免頻繁變化或短暫讀取失敗造成過密輪詢。超過 1.5 秒不以 current 發布。不同取樣之間可能發生變化，詳細 log 附取樣年齡及讀取耗時；不把診斷作操作授權或放寬停止條件。

詳細轉珠頁新增「戰況診斷」，複製紀錄新增 `battleObservation`。unknown 數值用 JSON `null`，失效後不再輸出舊數值；明示 `enemyForecastKnown=false`、`shieldReductionKnown=false`、`healingKnown=false`、`survivalKnown=false`、`lRecoveryAmountKnown=false`。不輸出帳號、原生指標或完整封包。

新增 15 組唯讀指紋，另行生成到 `PHOrbObservationTextGuards`。既有 114 組操作指紋維持原 gate；僅診斷指紋失配時隱藏觀察資料，普通求路／原生技能判斷仍走既有檢查。新增 observation 欄位不參與 `PHOrbSameAutomation` 等決策相等判斷。3／4／8 人與 3 人單人續玩不啟用這套單人診斷。
