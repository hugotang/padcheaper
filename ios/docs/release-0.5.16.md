# 0.5.16-orbs：補 L 規劃停止診斷

2026-11-01。源碼及回歸案例已完成，編譯與完整自動驗證待本次執行；結果更新於 [開發紀錄](development.md)。

缺珠或武裝資料讀取失敗時，診斷保留這次盤面、原有目標及原因，避免把上一回合的成功路徑當成這次結果。`solverStarted=false` 表示尚未開始求路，缺珠提示會列出實際需求，例如 T＋L 為 10 顆、方塊＋L 為 14 顆、只有一個 L 為 5 顆；轉轉仍使用全部共用相位的最低保證珠數。歷史中已執行的路徑保留，並標明與目前場次／回合／盤面的關係。

本版維持原目標加 L 的執行條件。**尚未加入「能擋下一擊就只排光 L＋心四」或「三光三心也放行」**；完整敵人下一擊、隊長盾、減傷、回血與延後解除判定仍待開發。詳見 [武裝回復 L](assist-recovery.md) 及 [敵方行動設計](enemy-aware-automation.md)。

使用者提供的 0.5.15 log 已觀察到：手動補成 18 光／8 心後成功執行光 T＋光 L＋心四，下一個穩定回合讀到武裝無效 2→0，再恢復原本光 T＋心四。這不能代替 0.5.16 的裝置驗收，也不證明 L 單獨解除的回合數。

真機重測：缺少保證光珠時確認停止、沒有新輸入，複製診斷應見本次盤面和 `planning-blocked`；補珠後成功回復則確認下一回合撤下臨時 L。保留原 config 即可，這次沒有新增設定。LiveContainer 替換 dylib 後重新簽署。
