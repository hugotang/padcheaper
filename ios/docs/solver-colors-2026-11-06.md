## 紀錄顯示的失敗

| 項目 | 紀錄／核對結果 |
|---|---|
| 版本 | 0.5.35-orbs |
| 盤面與操作 | 6×5、可斜移、最多 48 步、beam 512 |
| 目標 | `colors=31`、`count=5`，火／水／木／光／暗全部消到；心珠不替代攻擊色 |
| 初次求路 | 113 ms／800 ms 預算 |
| 原單人重試 | 77 ms／2000 ms 預算 |
| 工作總耗時 | log 記錄 191 ms，包含各次之外的工作開銷 |
| 所選候選 | `deadline=false`、`searchPasses=1`、`backtracks=0` |
| 原候選結果 | 6 Combo，但只有四個攻擊色，缺暗；因此沒有開放執行 |
| 珠數 | 火 8、水 5、木 4、光 5、暗 3、心 5 |

暗珠恰有三顆，起始零基底 row-major 格號為 0、2、27；沿紀錄中候選路徑交換後落在 0、1、22，沒有形成暗珠消除。足夠三顆只通過必要的庫存條件，不是可達路徑證明。原候選的 6 Combo 也不能替代五個不同攻擊色的交集要求。

這份 log 的主要問題不是已用盡 800 ms。原先純多色目標沒有進入形狀用的 recovery／多樣性保留；`NearColor` 對「三格中已有兩格」固定給 1365，不區分第三顆在鄰近位置或盤面另一端。主搜尋完成後，Session 又用更大時限重做相同的 deterministic 搜尋，因此新增時間未必產生不同候選。

## 本次來源調整

新增普通多色搜尋專用的補搜條件：無轉轉、非撈珠、非活動盤面目標，所有目標都是 colors 或 colors＋Combo，且 `minMatch <= minErase` 才可使用。來源明確要求 `!board.spinnerMask && fishCell < 0`，所有轉轉都排除，包括只有一種顏色或已鎖定的轉轉。多色沒有被當成 shape；轉轉、形狀及活動盤面的既有分支仍各自處理。

主搜尋仍使用原目標排序、完整 beam 與原本 deadline，不預先縮短為多色補搜保留時間。這只保留排序與時間額度；距離表預處理、逐候選時鐘檢查及淘汰候選尾部排序都會增加成本，不能宣稱原效能不變。只有主搜尋未達標、未逾時、未取消且尚有餘額時，才使用不同的引導：

- 補珠距離估計依可達格的距離區分缺色候選，集中照顧目前最弱的必要顏色；它只是樂觀提示，不是可拖到或可消除的證明。
- 補搜依缺色集合與布局保留不同候選，部分色罩／顏色數目標只需要該目標足夠的顏色，不把色罩中每一色都變成額外必選條件。
- 最多一次完整 recovery，另重訪最多兩份原 beam 淘汰的 frontier；補搜與重訪共用本次原始剩餘時間，仍受原有取消、步數及 beam 限制。普通無荊棘情況包含主搜尋最多四輪；有荊棘時，既有 no-contact 搜尋可能成為第五輪，本批未新增其他 pass。

最後候選仍經精確放開盤面評分與既有危險珠規則檢查。這份樣本的五色 `31/5`、48 步、beam 512、800 ms 初始額度沒有放寬，也沒有把缺色視為成功。原 `NearColor` 與主搜尋提示保持原樣；只有新增 `ColorGuidance` 的已達顏色紀錄依 `bonusFirstWave` 選用 `firstColors`，不另改原搜尋的首消提示。

## Session 重試與統計

單人延長搜尋只在結果為 `GoalsUnmet` 或 `Unsafe`、有有效保留候選、且候選明確 `deadlineReached=true` 時使用。已完整結束而未逾時的失敗記錄 `search-completed-without-deadline`，不再因失敗本身重跑相同搜尋。多人、assist 候選、取消、已用延長額度，以及沒有候選統計的終止狀態維持排除。

診斷分開保存每次 attempt、最後選中的 attempt 與整個工作的合計：每次實際預算／elapsed／wall elapsed、deadline 是否已知、evaluation／cache／pass／backtrack／depth、步數與 beam；選中索引及選中預算；總 evaluation／pass／backtrack、最大深度與總 wall elapsed。原本共用工作的預算欄位繼續保留，不再把最後一次或選中一次的數值當成全部搜尋量。候選缺失時明示統計不完整。
