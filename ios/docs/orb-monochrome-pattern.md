# 單轉轉、其餘同色盤面的 T 與四連限制

2026-11-07 的 0.5.41 裝置紀錄中，保留的失敗搜尋 generation 29 是 6×5 盤面：29 顆心珠、一個轉轉，目標為光 T 一組及心四連一組。可用時間為 390 幀／30 fps（13 秒），轉轉色表為六色、每色 15 幀；此次搜尋快照的轉轉是暗珠、倒數 8 幀。這是較早的失敗盤面，不能與最後一次已成功放手的 generation 33 混為一談。

這裡分析的四連是**首消中恰好四顆的直線消除群**。T 也必須是首消中恰好五顆的 T 形消除群。這與「四顆連線旁邊完全不能有同色珠」不同：未被消除標記的鄰珠可以存在，但已標記且相連的同色珠會擴大消除群。現有 [ShapeMatches 與首消判斷](../src/PHOrbSolver.cpp) 保持此語義；後續落珠不能補足這兩個形狀目標。

## 至少七次取珠是必要條件

以下下界只適用於 [PHOrbMonochromeEligibilityReason](../src/PHOrbMonochromeTemplate.inc) 確認的範圍：6×5、單一未鎖定的基本色轉轉、其餘 29 格同一供珠色、目標恰為另一色 T 一組與供珠色四連一組，普通三消規則，無荊棘、鎖珠及其他不支援的盤面限制。供珠色與目標色都必須在轉轉色表內。取珠次數沿用現有重複交換契約：不從轉轉起手，每次進入後必須退出，不能把起手持有轉轉的另一種操作當作免費取珠。

1. 完整放手路徑必須對轉轉所有可能終端顏色達標，因此必須包含「轉轉最後也是供珠色」這個情況。此時原盤沒有可免費保留的異色轉轉，每次取珠至多在其他格增加一顆異色珠。
2. 若供珠色四連水平排列，它占四個不同欄。這四欄各自至少需要一顆異色珠，否則該欄五顆全為供珠色，會整欄被標記並與四連相接，擴成大於四顆的消除群。此外，六欄盤面中的水平四連至少有一個仍在盤內的外端點；該端點必須是異色，否則延長為五連。這個端點屬於第五個不同欄。垂直四連同理，至少需要異色珠分布在五個不同列。
3. 五顆目標色形成的 T，在任一方向都只跨三列、三欄。如果總共只取五或六顆異色，T 之外最多剩一顆分隔珠；它最多再增加一列或一欄，總計仍只有四列／欄，無法滿足上述五列／欄條件。

所以，這個受限盤型要同時保證兩個形狀，**至少需要七次取珠**。七次只是必要下界；它不證明存在七次取珠的合法路徑，不證明 48 步內能排出，也不證明 13 秒內可執行。此結果不是「所有單轉轉盤都無解」，也不涵蓋改變目標、規則或放手條件後的盤型。

## 為何不能只縮短等待時間

既有 [AssistReserve](../src/PHOrbAssistFishing.inc) 每次取珠預留完整色輪。依此紀錄及 Session 的參數，五次取珠、每次進出各一步的最少十步，需要：

| 項目 | 保守預留 |
| --- | ---: |
| 十步移動，每步兩幀 | 20 幀 |
| 五次完整六色輪，每色 15 幀 | 450 幀 |
| 六次穩定等待，每次六幀 | 36 幀 |
| 輸入及擷取餘裕 | 12 幀 |
| 合計 | 518 幀 |

518 幀是**既有預留公式的計算**，不是找到的路徑、裝置實測時間或理論最短時間。它大於可用的 390 幀，所以原紀錄在搜尋幾何路徑前就因時間預留被拒絕；擴大搜尋運算時間不會解除這個限制。即使將這份預留算得更精確，五／六次取珠仍會遇到前述幾何下界。

[原生轉轉研究](../research/orb-multifishing-native-20261107.json) 的 N1–N4、N6 與 N8 表明：

- 各轉轉共用倒數；交換函式沒有重新設定倒數。持珠或移動中的珠子會跳過該次變色，不能視為從新的一輪開始。
- 進入轉轉前必須已看到目標色；持住該格不會讓持珠繼續變色。現有入口仍要求倒數至少六幀。
- 退出後留在轉轉的是供珠，須經原生移動與穩定。轉轉更新先於移動完成檢查，因此剛變穩定的那一幀仍可能已跳過一次變色。
- 供珠到下一個目標色之間，還有搬運、返回入口、等待與入口／出口確認；不能把供珠至目標的色距乘以週期當成每一段固定等待。

本次另以唯讀反編譯核對 `0x1005AB5F4` 與 `0x100608AC0`：前者扣共用倒數，到零時先重載週期，再依珠子狀態決定是否變色；後者交換指標並設定移動狀態，沒有重設此倒數。這項靜態證據不提供裝置上的固定穩定幀數上界。

未來若研究較長的取珠路徑，須在實際起手前重新讀取相位，逐次確認供珠、持珠及入口色序，並以不可延長的原生幀截止點限制穩定、搬運返回、進入及退出。到截止點未完成就停止並走既有持珠清理流程。路線移動與變色等待可以重疊計算，但必須有這些實際限制支持；不能以預覽相位、最短步距或假定的穩定速度替代。這套計算及執行流程本次沒有接入。

## 本次範圍及驗證狀態

本次僅新增受限盤型的幾何下界診斷及相關待執行案例，保留原有六次取珠上限、完整終端色序驗證及安全停止。沒有提供依賴指定放手顏色的路徑、提高取珠上限、改動轉轉／操作計時、擴大 Auto 或多人操作範圍。

未使用的時序計算草稿已移除。共用 solver 與主 solver 案例的嚴格 C++17 語法檢查通過，未產生物件檔或執行程式。Objective-C++／Foundation 及 Session 行為仍待驗證；沒有執行求路器、測試套件、產品建置、CI 或裝置操作。本頁的證明與預留公式不能當成實機通過紀錄。
