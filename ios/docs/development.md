2026-10-28，使用者要求先累積功能，等明確說「編譯測試」才一起建置與驗證。iOS GitHub Actions 已改為只有 `workflow_dispatch`；推送與 PR 不自動建置。

一般開發先修改程式、補測試案例並檢查差異、語法與設定格式。收到編譯測試指示後，再執行測試、iPhoneOS 編譯、模擬器檢查及打包；若失敗則修正後重跑需要的項目。交付檔必須來自通過檢查的同一 commit。

## 0.5.1-orbs：源碼開發，尚未編譯測試

- 7×6／5×4：讀取全部格子、依原生行列轉換、原生座標拖珠、最後一格放開及依尺寸繪製預覽。
- 求路品質：快速／均衡／深入，保存至 `config.json`，舊設定預設均衡。設定寫入成功才生效；切換後作廢舊預覽；執行中的路徑不更換品質。
- 步數依原生操作時間、frame 間隔及 4 秒執行上限縮短。深入模式不提高拖珠速度。
- 原生頁面固定返回與主要操作列，避免設定增加後需要捲到最底才可操作。
- 形狀目標：L／十字／T／3×3／整橫排／整直行／四連，另有連消、多色與最低 Combo。最多 6 項、指定珠色與組數，全部成立後才開放執行。原生編輯頁保存成功才發布；失敗保留草稿並顯示固定位置的錯誤。
- 隊長盤面：離線結構化資料帶入目前戰鬥雙隊長的部分最低盤面條件，未知規則阻止自動規劃並列出原因；HP、技能使用及覺醒／攻擊屬性有效性明示未評估。角色改變取消舊預覽／輸入，並在下次讀盤重新解析；原生按下或交換那一幀改變角色也須停止，不接受新角色接續舊路徑。詳見 [形狀與隊長盤面](orb-goals.md)。
- 一鍵連續：限目前單人關卡，先處理技能，再求路與確認原生轉珠，等消除結束及交換計數歸零後才進下一回合；技能 phase 不當成新回合。開始意圖不持久化，離場／背景／手動／多人／總開關關閉即停止。
- 技能規則：最多 12 條，可指定位置、當前角色編號、回合間隔、樓層、缺珠，以及敵人傷害吸收／屬性吸收／傷害無效／Combo 吸收。條件交集、優先順序、每位置每回合一次、施放完成確認與技能後重讀。採原生 can-use 與確認施放入口；編輯與保存失敗的草稿處理已加入。見 [連續轉珠與技能規則](orb-automation.md)。
- 特殊珠型／效果、轉轉及特殊消除規則仍不能直接轉珠；規則可先用技能補救，未解決仍停止。修正 `generate_orbs.py` 的舊 scope 字典與上一批目標 metadata 不一致問題，並加入技能欄位與指紋契約。
