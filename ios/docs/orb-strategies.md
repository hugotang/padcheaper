# 技能循環、策略檔與妨礙盤面

`0.5.1-orbs` 的技能循環、隊伍／關卡策略與妨礙盤面處理。編譯及自動測試結果見 [驗證記錄](development.md)；原生技能和鎖珠效果仍需真機核對。

2026-10-29 的 [盤面效果擴充](orb-effects.md) 已納入 0.5.3 集中驗證，最新結果見開發紀錄。下方妨礙表描述這批後續程式；既有 0.5.2 尚不能直接操作轉轉、特殊珠與其他新增效果。

第五批另加 [HP／我方異常自救與必要技能](orb-survival.md)，會隨這裡的策略一起保存。輪替組中的必要要求，以組內至少一個技能確認完成為準。

第六批新增的 [低血心珠設定](orb-recovery.md) 也隨策略保存。舊策略預設關閉，開始時選定的策略決定本次 HP 門檻與心珠要求。

0.5.6 新增 [隊伍＋開場＋循環＋盤面目標 config](team-plan-config.md)。可貼上、預覽、整批儲存及匯出；完整計畫另核對武裝、技能 ID 與開場變身進度。下方一般策略的本體配對及每回合限制，仍適用於一般循環；開場由獨立的順序流程執行。

## 技能循環

「編輯自動技能規則」新增下列可選欄位，舊規則不必改寫。

| 欄位 | 預設 | 行為 |
|---|---|---|
| `group` | 0 | 0 獨立施放；1–6 為輪替組，同組每個轉珠回合最多一個技能 |
| `once` | false | 相同內容的這條規則本場只嘗試一次；明確不可用不消耗，啟動不確定時也不重試 |
| `reserveUntil` | 0 | 把此位置保留至指定樓層（1–999）；同位置所有規則一起受限制，0 不保留 |
| `obstacle` | none | 妨礙條件，與原有角色、間隔、樓層、缺珠及敵人條件取交集 |

輪替組的優先度由最上方成員決定。組內從上次被原生接受的技能之後開始找，找到末尾後繞回頂部；條件不符或技能不可用可換下一名。原生接受後鎖住本回合的整組，其他加速技能不會讓同組再放第二次。每位置每回合一次的限制仍然保留。

例如把兩個產珠角色放進同一輪替組，可輪流接續而不在同回合一起消耗。開場變身可另設獨立規則、限定變身前角色編號及 `once: true`。需要保留解吸收技能到第 5 層時，將該位置的 `reserveUntil` 設成 5；這也會限制此位置其他規則，包括開場變身，請按隊伍需求分配位置。停用規則不保留技能；多條保留條件採最晚樓層。

```json
[
  {"enabled": true, "slot": 2, "monster": 0, "every": 1, "floor": 0,
   "color": -1, "below": 0, "enemy": "none", "group": 1, "once": false,
   "reserveUntil": 0, "obstacle": "none"},
  {"enabled": true, "slot": 3, "monster": 0, "every": 1, "floor": 0,
   "color": -1, "below": 0, "enemy": "none", "group": 1, "once": false,
   "reserveUntil": 0, "obstacle": "none"}
]
```

停止後重開仍保留本場的輪替順序、一次性紀錄及當回合使用位置／群組。明確觀察到有交換的消除階段，再返回穩定操作階段且交換次數歸零，才清除每回合紀錄；技能 phase 22、切層或短暫讀取失敗不會清除。啟動不確定的技能也保留位置／群組的本回合限制。

一次性紀錄以正規化後的完整規則內容比對；修改條件視為新規則，調整順序不影響。下一次開始採用不同規則時會重設輪替順序，但不清除當回合位置／群組限制。停止後介面回載通用設定不會清除實際執行策略的輪替紀錄。本場一次性紀錄最多 128 筆，超過即停止。所有紀錄只在目前程序內有效；確認離場／新場、切換帳號或完整重啟後重新開始。回合間隔仍從每次按「開始」算第 1 回合。

## 隊伍／關卡策略檔

轉珠頁新增「隊伍／關卡策略」，可保存最多 64 份，新增、命名、複製、刪除及選用。策略把技能規則、盤面目標和求路品質一起保存。選用後在轉珠頁修改設定，會在同一次 `config.json` 寫入中更新該策略；任何寫入失敗都保留原設定及編輯草稿。回讀確認策略庫與實際設定皆相符後才關閉編輯頁。

一般策略可從既有隊伍庫帶入六個本體圖鑑號碼，也可取消助人限制。號碼 0 不限定該位置。一般策略只配對開始時的角色形態；0.5.6 的完整 config 則核對六格本體與武裝。兩者均不以等級與覺醒作配對條件；綁定資料不會隨隊伍庫編輯而默默改寫。

先在關卡讀盤，再用「帶入最近讀盤的關卡」綁定地下城及子關卡。這些 ID 與技能規則的「第幾層」不同。可取消隊伍或關卡限制，建立明確的通用策略。

預設手動選用，開始前仍需符合該策略的綁定。另可開啟「按開始時自動配對」，在**明確按下連續開始時**選擇一份：

1. 優先完整地下城＋子關卡，其次只有地下城，再其次不限關卡。
2. 同一類關卡限制內，以限定角色位置較多者優先。
3. 最高優先度有多個候選或沒有符合者就停止，不猜選第一份。

策略只在本次開始時決定；後續變身、技能進化及切層不重新配對，也不切換規則。開關不會自動選關、進場、重開戰鬥或開始輸入。選到的策略與停止原因保留在回合紀錄中。

設定保存在頂層 `orbProfiles`：

```json
{
  "schema": 1,
  "selected": "team-a",
  "autoSelect": false,
  "profiles": [{
    "id": "team-a", "name": "隊伍 A 產珠循環",
    "team": [100, 101, 102, 103, 104, 0], "dungeon": 0, "floor": 0,
    "settings": {"quality": "balanced", "mode": "combo", "goals": [], "rules": []}
  }]
}
```

`selected` 空字串表示不綁策略的通用設定。手動選用的策略 `settings` 必須與頂層 `orbs` 的正規化設定一致；GUI 會原子更新兩者，手改設定檔也需同步。自動配對只改本次執行的設定，不在 frame 內寫入設定檔。舊設定沒有 `orbProfiles` 時維持通用設定及關閉自動配對。

## 妨礙盤面的處理

這批新增可選的 `obstacle` 條件：

| 值 | 條件／目前範圍 |
|---|---|
| `none` | 不限定妨礙 |
| `locked` | 至少一顆鎖珠，仍須符合該珠型及其他效果限制 |
| `spinner` | 原生轉轉仍有效；後續程式可避開轉轉格並枚舉全部共用色序，不按時抓色 |
| `unmatchable` | 原生不可消效果仍有效 |
| `weakened` | 至少一顆珠的強化值為負；新批次保留符號與幾何消除，不估算傷害／回復 |
| `special_orbs` | 基本六色以外的珠；保留舊條件，另有各珠型的獨立條件 |
| `jammer`／`poison`／`mortal_poison`／`bomb` | 邪魔／毒／猛毒／爆彈，可分別指定補救技能 |
| `cloud`／`tape` | 雲／封條；雲可正常規劃，封條格不能進入 |
| `blind`／`super_blind` | 普通暗闇／超暗闇，使用底層真實珠色 |
| `nail`／`thorn`／`combo_orb` | 釘珠／刺珠／Combo 珠；路徑避開刺珠，不加算額外傷害與 Combo |
| `fixed_start`／`match_rule` | 固定起點／最少消珠限制，求路必須服從 |
| `orb_effect` | 尚未支援的珠旗標；已核對的暗闇、鎖、釘等旗標有各自條件 |
| `board_effect` | 未通過欄位校驗或尚未建模的盤面效果 |

共同流程是「符合條件 → 嘗試使用者指定的原生技能 → 等完成確認 → 重新讀盤」。這只是觸發條件，不代表自動知道哪個技能能解除它。最後盤面仍不支援、資料不明或未達目標／毒彈限制時停止；已支援效果可以依其限制繼續求路。必要技能、隊伍／樓層保留與群組限制仍優先。

強化與鎖珠原本已支援。後續原始碼加入弱化值及已核對的其他旗標，完整保留並隨珠交換；鎖珠混有轉轉、毒珠等情形仍套用各自限制。沒有直接清除遊戲的鎖珠或妨礙旗標。

### 轉轉的有限適配

已交付 0.5.2 只能辨識轉轉並嘗試指定解除技能；轉轉持續時不能直接轉珠。後續原始碼讀取位置、色表及週期，允許多格以共用相位推進。所有相位都達成目標且沒有毒／爆彈違規才可執行；不穿過任何轉轉格。鎖珠的顏色固定，但所在轉轉格仍不走。**尚未加入抓變色時機、等待指定顏色或拖動中取色的求解器。**

每一步仍核對全盤 token、旗標、遮罩、相對色序與交換次數。變色容差不能掩蓋換珠、獨立改色、尺寸或效果變更；不一致便取消。技能缺珠條件與低血補心也採共用相位的珠數範圍，避免使用某一瞬間的顏色作保證。

雲／暗闇類使用底層珠色；封條／固定起點加入路線限制。毒／猛毒不允許確定性消除，爆彈要求首批全消，刺珠不接觸。尚無血量與傷害／回復試算；詳見 [效果適配與待驗證](orb-effects.md)。

## 靜態依據與待驗證

目標仍為日服 23.6.0／106878。IDA 靜態對照：

- `0x1005ABF34`：`block +4` 的 `0x800` 鎖珠 gate；`0x1005BEEE0` 在技能轉色前呼叫它並拒絕改色。
- `0x100608738` 原生交換與 `0x1005FC5CC` 消除計算：鎖珠不改普通三連及交換的幾何規則，旗標仍須跟隨珠保留。
- `0x100565EEC` 設定轉轉：`impl +739360` 持續時間、`+739380/+739396` 間隔／初始計時、`+739412` 起六列位置遮罩；依原生 frame rate 換算時間。`0x100565B20` 增加指定位置，`0x1005659C0` 清除效果。新批次另核對 `0x1005AB350` 的共用倒數／色表及鎖／動畫例外；只採避開所有轉轉格的策略。
- 0.5.2 的 26 筆指紋保留，後續效果批次另增 10 筆，共 36 筆；只做版本校驗，未新增對這些函式的直接呼叫。

自動測試涵蓋規則舊格式相容、輪替／不可用替補／加速防重複、保留樓層、停止重開／新場一次性紀錄、策略匹配／衝突／錯隊停止、停止後回載通用設定再開始的輪替紀錄、設定一致性、妨礙解除後重讀／轉轉持續變色拒絕、鎖珠與其他效果混合、GUI 鍵盤／失敗草稿／成功回讀與遊戲焦點還原；執行結果見 [驗證記錄](development.md)。

真機仍須驗證新增原生欄位、鎖珠的實際交換與消除、各解除技能、不同轉轉模式、變身後保持策略，以及低 frame rate 下的讀取負擔。靜態對照及函式替身不等同實機成功。
