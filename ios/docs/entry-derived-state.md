# 入場數值與套用時機

`0.4.4-entry`；日服 PAD 23.6.0／106878。這份核對區分隊伍衍生數值、新入場初始化及已生成的關卡狀態。原生函式替身測試不等同真機技能、多人同步或伺服器結算驗證。

## 哪些數值需要處理

| 項目 | 現有流程及本版處理 |
|---|---|
| 成員 HP／攻擊／回復、武裝、覺醒、技能參數 | `0x1005a12f0` 依本機配方重建成員。實際傷害與技能效果仍由遊戲在觸發時計算，不能用一個固定「總攻擊力」代替。 |
| 最大 HP、隊伍回復、隊長／徽章及條件效果資料 | `0x10006f798(game, 0)` 經 `0x10006fb04`、`0x10006a308`、`0x10006f64c` 更新；原有交易已呼叫此流程。 |
| 操作時間 | 上述 refresh 會呼叫 `0x100604580`，依隊伍覺醒、潛覺、徽章、隊長及關卡的固定／增減秒數規則更新。不能直接把延長覺醒相加後覆蓋關卡限制。 |
| 初始 Skill Boost | 整隊完成後計算一次，沿用原生 SB、SB+、SB prism、SB minus、潛覺、徽章及技能上限；仍保留原生禁用規則。 |
| 入場目前 HP | **本版補上。** 普通 refresh 只會保留／裁切目前 HP，新最大 HP 增加時不會自動填至新上限。新入場在整隊及 SB 完成後，以 `0x1005fb690` 取得有效最大 HP，再用 `0x10060701c(controller, maximum, 1)` 初始化 HP 及顯示。 |
| HP／隊員摘要／技能充能的保護值及鏡像 | 每次交易核對一致性，HP 初始化後再核對有效上限、隊員、充能及其他 bank；失敗回復已確認的原隊伍與數值，不清除原生異常旗標。 |
| 7×6 盤面及已生成的開場盤面 | **本版不重新生成。** 建構函式 `0x1005b6488` 在進入 phase 0／46 前，已選擇 `game + 88/89` 的盤面尺寸並呼叫 `0x1005f3d54` 初始化盤面。隊伍 refresh 更新相關效果資料不等於重建這些盤面狀態。 |

`0x1005fb690` 會處理固定 HP、負值表示的關卡比例規則及目前 HP 上限修正；不能只讀取 raw max HP。新入場的 HP 初始化只對選中的本機 bank 執行，再由普通 refresh 保存。沒有將全隊 refresh 的參數改成 1，避免其他參與者也被重新初始化 HP。

guest 的後續補回只保留同步後 HP，最多依新上限裁切；保留已用技能／先制延遲後的充能，不重發 SB，也不重播入場效果。若對方同步傳回不同 HP／充能，入場計算結果不代表同步後仍保留相同數值。

## 能否更早

新入場本來已逐 frame 等待第一個有效的 phase 0／mode 7 phase 46，要求建構完成、wave 0、非恢復、serial 0、輸入放開。它不受一般 250 ms 診斷節流限制。

本版取消的是**成功入場後監測多人綁定的 250 ms 節流**：只要仍持有可補回的自動入場配方，就在每個原生 frame 結束後檢查。自己的隊伍、回合、輸入及交易校驗首次符合條件時，即在該次回呼內補回全部待補位置。沒有刻意再等 250 ms，也不逐格等六個 frame。

`0x10001b6a4` 在 phase 48 內套用 `0x10001771c` 快照、推進回合、refresh，接著在同一次函式呼叫設為 phase 2。現有 `ViewController.drawFrame` 的 IMP hook 位於整次原生更新／繪圖之後；phase 48 的中途不能視為同步完成。把同一檢查單純搬至下一個 drawFrame 前，讀到的仍是上一個已完成 frame 的狀態，不能取得更早的同步完成時點。

因此目前是這個 hook 下第一個已驗證可操作的時點，並非宣稱所有架構能做到的絕對最早。若要在建構盤面之前套隊，或在同一 frame 的原生更新後、繪圖前接入，需另做更內層的 hook 與完整生命週期驗證；直接提早寫入仍可能被建構或下一份快照覆蓋。

## 驗證

原生 fixture 覆蓋單人、兩人／三人各席位、整隊／部分替換、HP 上限增減與有效上限不同於原始加總、只更新本機 HP、畫面復原、HP 失敗還原、異常旗標保留、其他 bank 汙染拒絕，以及後續補回保留受傷 HP。session fixture 用相隔 10 ms 的連續 frame 驗證同步完成後立即補回，並驗證 phase 48 不寫入。真機畫面延遲、操作秒數、入場 HP 與 guest 補回仍待裝置核對。
