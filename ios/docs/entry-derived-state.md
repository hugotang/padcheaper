# 入場數值與套用時機

`0.4.5-solo`；日服 PAD 23.6.0／106878。以下流程現在僅用於單人；多人已停用。本文件區分隊伍衍生數值、新入場初始化及已生成的關卡狀態。原生函式替身測試不等同真機技能、多人同步或伺服器結算驗證。

## 哪些數值需要處理

| 項目 | 現有流程及本版處理 |
|---|---|
| 成員 HP／攻擊／回復、武裝、覺醒、技能參數 | `0x1005a12f0` 依本機配方重建成員。實際傷害與技能效果仍由遊戲在觸發時計算，不能用一個固定「總攻擊力」代替。 |
| 最大 HP、隊伍回復、隊長／徽章及條件效果資料 | `0x10006f798(game, 0)` 經 `0x10006fb04`、`0x10006a308`、`0x10006f64c` 更新；原有交易已呼叫此流程。 |
| 操作時間 | 上述 refresh 會呼叫 `0x100604580`，依隊伍覺醒、潛覺、徽章、隊長及關卡的固定／增減秒數規則更新。不能直接把延長覺醒相加後覆蓋關卡限制。 |
| 初始 Skill Boost | 整隊完成後計算一次，沿用原生 SB、SB+、SB prism、SB minus、潛覺、徽章及技能上限；仍保留原生禁用規則。 |
| 入場目前 HP | **自 0.4.4 加入，單人保留。** 普通 refresh 只會保留／裁切目前 HP，新最大 HP 增加時不會自動填至新上限。新入場在整隊及 SB 完成後，以 `0x1005fb690` 取得有效最大 HP，再用 `0x10060701c(controller, maximum, 1)` 初始化 HP 及顯示。 |
| HP／隊員摘要／技能充能的保護值及鏡像 | 每次交易核對一致性，HP 初始化後再核對有效上限、隊員及充能；失敗回復已確認的原隊伍與數值，不清除原生異常旗標。 |
| 7×6 盤面及已生成的開場盤面 | **本版不重新生成。** 建構函式 `0x1005b6488` 在進入 phase 0／46 前，已選擇 `game + 88/89` 的盤面尺寸並呼叫 `0x1005f3d54` 初始化盤面。隊伍 refresh 更新相關效果資料不等於重建這些盤面狀態。 |

`0x1005fb690` 會處理固定 HP、負值表示的關卡比例規則及目前 HP 上限修正；不能只讀取 raw max HP。整隊完成後才初始化新入場目前 HP，手動替換不補滿受傷 HP。入場失敗時僅在仍為同一單人戰鬥的可驗證狀態嘗試回復；一旦切成多人，停止後續寫入。

多人時其他玩家沒有本機配方，重建上述本機數值不能解決同步。使用者已回報本機與其他玩家隊伍不一致及斷線，故本版刪除多人補回及 HP 校正路徑。

## 能否更早

單人新入場逐 frame 等待第一個符合檢查的 phase 0，要求建構完成、wave 0、非恢復、開場旗標及輸入放開；不受一般 250 ms 診斷節流限制。同一次回呼完成整隊、SB 與 HP，不逐格等待六個 frame。

現有 `ViewController.drawFrame` 的 IMP hook 位於整次原生更新／繪圖之後。因此這是現有 hook 第一個符合校驗的時點，不能稱為所有架構的絕對最早。將檢查搬到下一個 drawFrame 前，讀到的仍是上一個已完成 frame 的狀態。

若要在建構盤面之前套隊，或同一 frame 的原生更新後、繪圖前介入，需另行驗證更內層 hook、資料生命週期及可能被建構覆蓋的欄位。目前未實作；多人也不會因更早寫入就自然同步。

## 驗證

原生 fixture 保留單人整隊／部分替換、HP 上限增減、固定／比例有效上限、HP 顯示、失敗還原及異常旗標保留；SB 涵蓋武裝、超／潛覺、徽章、技能上限與禁用規則。多人測試改為證明零 native call／零寫入，沒有繼續模擬「補回即成功」。

使用者已確認 0.4.1 單人套隊與 SB 成功。HP、操作秒數、實際技能與先制效果、畫面時機及結算仍需真機核對。
