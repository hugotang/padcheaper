## 可確認的停止原因

兩次 B4 攻擊分別走完 34／34、43／43 步，放手已確認。求路前與放手前皆為敵方效果 `2`、我方 bypass `7`、未覆蓋 `0`。最後一盤結算後，前兩敵死亡，第三敵 `202576` 剩 `107181196233 / 320000000000` HP（33.49%），bypass 變成 0，才出現未覆蓋屬性吸收。這不是上一盤被吸收的證據。

原始兩條路線都符合舊版「首消六色＋心四」；這個可執行條件不等於攻略的全力攻擊。兩盤固定珠庫存（不含轉轉格）分別是 `[5,8,4,8,8,8]`、`[8,6,8,6,6,7]`，每色至少四顆；缺少四消不能直接歸因為盤面缺珠。庫存足夠也不證明 48 步或手機預算內一定有解。

## 攻略與原生資料

- [GameWith](https://xn--0ck4aw2h.gamewith.jp/article/show/585607) 的基本規則是五色＋回復盡量多組四消、每次心四；B4 是 Solomon→Keisy→Atori 全力，接 Atori 全力。文字沒有給「兩組四消便足夠」的擊殺門檻。
- [AppMedia](https://appmedia.jp/pazudora/80564326) 明列基本「6色4個消し」，B4 有木吸收敵人時指定該敵人，兩次削血。此處是敵人**吸收木屬性**，不是木屬性的敵人。
- 本場兩位 Atori 都是專用技能 `66711`。固定來源資料記錄「每組四顆攻擊力 3 倍」，雙隊長每增加一組的隊長倍率比為 9。這只說明低四消數的重大落差，不計個別隊員倍率、上限、弱化珠、屬性、敵人防禦、指定命中及實際傷害。
- 歷史紀錄 `targetSlot=0` 的程式語義是**沒有明確指定目標**；不是零起算的第一敵人。本次已補匯出語義。
- 停止時第三敵吸收遮罩為 `1`（火），不是木。前兩敵的過期診斷沒有保留當時的個別吸收色，不能從敵人 ID 推測，也不能認定缺少木吸收指定是本次唯一敗因。

資料雜湊、節錄、原盤／路線、各時點 HP 與限制見 [最小化分析紀錄](../research/coral-b4-20261119.json)。私人原 log 不提交。

## r6 來源修正，0.5.58 驗證候選

1. B4 兩盤明列 `board.requireSixColorFours: true`。普通求路與取色使用六個逐色四顆目標；原契約也核對首消四顆顏色遮罩 `63`，每個相關轉轉相位都需成立。只提高總四顆數、後續連鎖補四顆或只有心四不能放行。搜尋未取得完整合格路線便停止，不回退成舊版弱攻擊。
2. B4 明列完整敵人 `202575/202578/202576`，兩盤技能完成後要求新鮮傷害吸收／屬性吸收／傷害無效覆蓋。維持原本技能順序及兩盤上限；不在效果到期後硬加第三盤。
3. 新增條件目標 `target: attribute_absorb, color: 2`。每次以兩次一致的原生敵人身分、HP、受保護的吸收色／回合數決定。完整確認沒有木吸收才可略過；未知即停止。有多個符合者時保留目前符合的指定，否則選最前面的原生位置。僅一個敵人存活時不點不存在的切換窗口。
4. 首盤技能前及後、收尾技能後覆核目標。求路、預覽與拖珠的原生敵人比對包含吸收色／回合數；點選缺少原生回覆或資料變更即停止。匯出的逐盤資料保留個別吸收色，避免下一次只剩彙總遮罩。
5. 上限訊息明確說「回合結束後」的未覆蓋狀態，不推定前次出手失敗。

r6 是新 ID，由 0.5.58 候選引擎支援；0.5.57 不接受新欄位。本候選已完成編譯但未通過搜尋驗收，未交付。現有 r5、已交付 dylib 和 E:/ipa 版本均保留。這次來源修改的可驗收承諾是「不再把缺少逐色四消的 B4 當成合格全力攻擊」，不是「已證明 B4 或全程通關」。

## 本次編譯測試與功能驗收

使用者已明確要求編譯測試。Windows 可攜回歸、Python 版本／目錄、JS 編隊／隊伍／地城與 Edge 編輯器已通過；原生、Session、sanitizer、iPhoneOS 與四份 iPhone GUI 已通過手動 [CI 186](https://github.com/hugotang/padcheaper/actions/runs/44551918880)，完成結果見[開發紀錄](development.md)。

兩張原盤的普通搜尋以 beam512、48 步、800／2000ms 各三次均未取得合格六色四消。共享提示、稀缺色優先、供珠去重、整體布局與補搜實驗沒有通過兩盤，因此未納入 runtime。單次與連續取色另以相同來源重測；連續取色的時鐘只使用停止時觀察到的 810 frames／30fps／週期30作條件假設，不代表前一盤當時的原生時鐘已知。

探針 [coral_b4_six_fours_probe.cpp](../research/coral_b4_six_fours_probe.cpp) 使用實際原盤及強化珠資訊：退出 0 為全部合格、2 為搜尋驗收未過、1 為 API／重播無效。CI 保留搜尋失敗並繼續原生／編譯檢查；CI 綠燈不能把 exit 2 變成成功。**本版不建立正式交付**，仍須解決原盤搜尋，才進入 B4 傷害／目標、B5 技能銜接及整場真機驗收。
