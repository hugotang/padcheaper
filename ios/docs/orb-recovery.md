# 低血時的心珠目標

`0.5.1-orbs` 的低血心珠目標，預設關閉。編譯及自動測試結果見 [驗證記錄](development.md)；實際技能後的 HP／盤面與心珠路徑仍需真機核對。

## 使用方式

在自動轉珠頁開啟「低血時的心珠目標」，設定 HP 門檻、心珠組數及形狀。儲存成功後與目前選用的隊伍／關卡策略一起生效；失敗保留草稿。

| 設定 | 預設 | 行為 |
|---|---|---|
| `hpAtMost` | 0 | 0 關閉；1–100 表示 HP 不超過有效上限的此百分比時啟用，包含等於門檻 |
| `groups` | 1 | 需要 1–3 組獨立的心珠消除；連成一大團只算一組 |
| `shape` | `match` | `match` 為每組至少三顆；`four` 為首批消除的四顆直線，周邊不可連同色珠 |

只在使用者按下「開始連續轉珠」後套用。每個回合依序處理技能、確認完成、重新讀盤與 HP，再加入心珠目標。回血技能已讓 HP 高於門檻時，不額外要求心珠；造心技能產生的珠子可供這次求路使用。

「讀盤並求路／執行一次」仍只使用原有目標，並顯示本次未套用低血心珠；不為手動預覽增加 HP 讀取。舊設定沒有 `recovery` 時預設關閉。

## 與原有目標、必要技能的關係

心珠要求與高 Combo／手動形狀／隊長盤面目標取交集，全部達成才可自動執行。同形狀、同珠色、同連消長度的目標取較高組數；不相同的目標保留。合計超過六項時停止並說明原因，避免遺漏原有條件。

例如原有目標要求木直行，低血時可再要求兩組心珠至少三連。原有目標若已要求三組心珠至少三連，低血設定要求兩組，仍須完成原來的三組。不同形狀能否由同一個消除群組同時滿足，沿用既有 [目標判定](orb-goals.md)。

[必要技能](orb-survival.md) 的完成要求先於求路。即使心珠足夠，也不會因此放行仍未完成的必要技能。不可消、轉轉、弱化珠及其他未支援效果的限制繼續生效，普通鎖心珠可使用。

啟用低血心珠但 HP 或有效上限無法確認時停止。低血盤面的實際心珠數不足時，求路前即停止並顯示目前與最低所需數量。心珠數足夠只代表可以搜尋；路徑仍須達成全部目標，未達標不自動執行。求路之後 HP／上限／我方狀態改變會取消舊決策；若已持有拖珠，沿用既有放開流程。

「至少三連」可計入現有珠子落下後的盤內連鎖；四顆直線只計首批消除。兩者都不計隨機天降。不估算回復量、有效覺醒或敵人傷害，因此完成心珠目標不代表一定回到 HP 門檻或能承受下一次攻擊。

## 設定與顯示

`orbs` 設定片段：

```json
{
  "quality": "balanced",
  "mode": "combo",
  "goals": [],
  "rules": [],
  "recovery": {"hpAtMost": 40, "groups": 2, "shape": "match"}
}
```

策略的 `settings` 使用相同格式。手動修改設定檔時，若已有選用策略，頂層 `orbs` 與該策略的正規化設定須保持一致；GUI 會用同一次寫入完成。舊策略的四個欄位仍可載入，新策略可增加 `recovery`，無需修改 schema。

主頁顯示已儲存設定，以及最近一次「高於門檻／已要求心珠／資料未知／心珠不足」的判斷與回合編號。路徑預覽逐項顯示合併後的目標與達成數。停止後的結果是最近紀錄，不代表背景持續判斷。從隊長盤面轉成自訂目標時只複製原有隊長條件，不把這次低血才需要的心珠永久存成手動條件。

實作沿用第五批的唯讀 HP 資料及現有消珠求解器，沒有新增原生入口或寫入 HP／效果／冷卻。目標 metadata 與 generator scope 同步；程式指紋仍為 26 筆。

## 驗證範圍

自動測試涵蓋門檻邊界與寬整數比較、三種盤面末格與鎖心珠、組數／形狀與原有目標合併、六項上限、未知 HP／多人／未支援盤面拒絕；技能回血、造心與消除心珠後重讀；必要技能優先；手動模式不套用；求路後掉血取消與按下當幀的持珠放開；品質／心珠設定變更使舊預覽失效；策略與設定保存、GUI 實際控制事件、保存失敗草稿、成功回讀、遊戲焦點還原及隊長條件轉自訂。

真機另驗不同回復力隊伍的預期是否合理、三種盤面上的多組心珠路徑、四顆直線、複合技能後 HP 及盤面讀取時機。交付來源與實際執行結果見 [驗證記錄](development.md)。
