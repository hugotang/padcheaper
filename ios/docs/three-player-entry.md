# 多人戰鬥限制與同步依據

`0.4.5-solo` 已停用所有多人戰鬥寫入，移除本機 bank 套用與同步後補回。

2026-10-28，使用者回報 0.4.4 在多人時只有自己看見替換，其他玩家仍見原隊伍、數值未如預期重建，而且會斷線。先前 0.4.2 host 回報與 fixture 成功只證明曾看到本機替換，不能證明多人隊伍、戰鬥數值或結算一致。斷線可能與狀態差異相關，但尚未證實服務端具體拒絕原因。

## 為何不能靠本機補回

`0x10001771C` 依接收快照重寫每一隊的成員，再呼叫 `0x100019BBC` 和 `0x10006F798` 重建。成員 `+0x128` 的腳本綁定來自快照 byte 22，充能 `+0x1c8` 來自 byte 38 的 uint16；本機租用的 44-byte 配方並不在這份同步資料中。phase 48 的 `0x10001B6A4` 在換回合時再次採用快照。

因此，重建本機成員、HP 或摘要，不能讓其他玩家取得同一份配方。反覆補回只是維持本機差異，不能視為多人同步方案。0.4.3／0.4.4 的本機補回測試不足以驗證真實協作遊戲，現已撤回這條路徑。

## 本版限制

- `multi != 0` 或 `mode == 7` 在任何 phase、任何席位、任何 allow-all 設定下均禁止寫入。
- 偵測多人後，直到確認離開戰鬥前都不恢復寫入，避免斷線／selector 回零重新放行。
- 手動套隊、變身、入場 SB／HP、補回、還原及計時干預均停止。舊排程取消，不呼叫原生還原或釋放舊參數。
- 多人診斷只從記憶體解碼基本狀態，不讀取隊伍 bank、不呼叫原生 getter／digest。
- 單人套隊與一次性入場 SB／HP 保留。更新後需要完整重啟遊戲，使舊注入程式退出。

## 已保留的靜態依據

以下是同一遊戲版本的靜態位置，不代表功能仍啟用；沒有加入使用者完整裝置診斷。

| 位置 | 用途 |
|---|---|
| `0x1005b6488` | 建構所有隊伍、逐隊計算初始 SB，multi 1 最後設為 phase 46 |
| `0x10001afb8` | phase 46 同步完成後轉入 phase 0 |
| `impl + 0xa3e48` | 回合計數；取隊伍數的餘數得到回合擁有者 |
| `impl + 0xa3e4c` | 本機連線席位；`0x10000be9c` 從本機連線記錄初始化 |
| `impl + 0xa3e58` | 畫面載入的隊伍，可能因預覽／原生 refresh 暫時改變 |
| `impl + 0xa3e5c` | 共用隊長／助人的來源選擇，不是本機席位欄位 |
| `0x10060d1f0` | 原生 phase 2 對照回合餘數與本機連線席位 |
| `0x10000cee0` | 載入選定隊伍及其 HP；保留靜態依據，已停止呼叫 |
| `0x100019ff0` | 保存本隊 HP 到 bank + `0x6c48`，設 descriptor bit 4 |
| `0x10001771c` | 接收快照逐隊重寫 script 綁定、變身、充能等欄位，之後重建隊伍 |
| `0x10001b6a4` | phase 48 換回合時採用快照，再切換回合擁有者 |
| `0x1005a12f0` | 綁定大於 0 且 script program 存在時才使用對應的 44-byte 配方 |

## 驗證範圍

測試檢查多人入口及每一席位不能呼叫 native 函式、配置／釋放、隊員重建、bank 切換、充能或 HP 更新。過期單人快照、舊 allow-all、壞保護值／未初始化 bank、待執行還原、原生呼叫途中變多人、selector 回零以及下一場單人皆有覆蓋。

這些是停用行為與單人回歸測試；沒有把伺服器或其他玩家的遊戲執行環境當成 fixture，也不宣稱真機斷線問題已經獲得根因驗證。
