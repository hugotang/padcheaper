# 五色＋心三連／轉轉：3 人轉一次調查

2026-11-07，使用者提供 0.5.39-orbs 真機 log，詢問求路算法可優化處。下方調查記錄交付版的行為；同日後續已授權來源修改及 3 人手動「轉一次」fishing，接入狀態見文末。[整理後證據](../research/solver-colors-spinner-20261107.json)保留原調查方法與資料，不含私人原始 log。

三顆暗珠從格 `0／17／20` 落到 `0／23／6`：左上角格 0 完全沒被路線碰到，最後只有格 0／6 的一對，另一顆在格 23。獨立交換及六相位連鎖消除均符合 log，不是某一種轉轉顏色才失敗。盤內沒有封條或指定起手，避開轉轉後 29 格仍相連；固定珠數足夠是必要條件，不是 48 步內有解的證明。

最後失敗路線及保留的三條成功路線都沒有完整珠子身分循環，這次不以去循環為主要方向。最近成功的三條均確認放手，12／15／22 步、搜尋 111／102／122 ms、執行 901／1,099／1,600 ms，全部消到五色＋心；那些盤沒有轉轉，不能據此比較相同盤面的效能。`observedBoardPreserved` 保留的是先前已確認盤，`metadata-only` 不是新取得的放手後完整讀盤。

## 0.5.39 來源中的兩個獨立缺口

1. 多色補搜入口當時只允許無轉轉且所有目標都是 Colors／Combo。這盤既有轉轉，又有 `Match(心,3)`，兩個條件各自都會排除它。五色及普通 Match 也不算 shape，故補搜與保留分支均未開啟。主搜尋走完 48 層就結束，剩餘約 346 ms 沒有轉用不同引導；單純增加毫秒上限不會自動增加這些分支。後續修改位置為 [PHOrbSolver.cpp](../src/PHOrbSolver.cpp)。
2. Session 的單次／連續 fishing 當時都要求單人，且原生輸入再次禁止多人進入轉轉。這次停用原因是 3 人模式，不是按「轉一次」本身。延長重試也限單人且須原候選逾時，本次未符合。不要把空 `fishingPlan` 或 `started=false` 解讀為取色求路已失敗。後續接入位置為 [Session](../src/PHOrbSession.mm) 及[原生輸入](../src/PHOrbNative.mm)。

## 優先改善方向

- 先把「多色＋至少一組基本色三連」納入缺色引導，保留原目標的完整語意，不把任意 Match 長度／組數一律改成顏色有消即可。這盤應將稀少的三暗與三心一併保護，保留先接近暗珠、暫時 Combo 較少的不同分支。
- 讓避開轉轉的路線使用上述引導與原預算剩餘時間，有界地重訪不同布局。提示不能依賴轉轉當下顏色；需考慮固定可用珠、合法搬運距離及六相位最差結果，最終仍精確重播所有相位。
- 明示未補搜／未取色原因及每個失敗相位的缺色集合，例如「多人模式未啟用 fishing」「五色缺暗」，避免把少一色、缺珠與入口未開混為一談。

上述為初次調查的建議順序；仍未生成新的原盤路徑，尚不能宣稱改善已能解此盤。

## 同日來源實作，尚未編譯測試

使用者後續確認包含 3 人手動一次、不開 3 人 Auto。普通路線已允許「多色＋一組單色最低連線 Match」進入缺色補搜；提示只看固定珠及避開轉轉的模板，先合併全相位精確結果再挑缺色，不改各目標的放手判定。更長 Match、多組 Match、精確形狀與活動模式各自保留原搜尋規則，不一律化成顏色存在。

單人一次／連續與已綁定本機回合的 3 人手動一次接入 fishing。3 人普通搜尋先用最多一半設定時間，取色各候選共用剩餘期限；單人原有有界回退與逾時政策保留。取色預算由移動鐘和回合鐘共同限制，等待／交換過程逐次檢查穩定狀態、色表、顏色、身分與剩餘步驟，換手就撤銷。4／8 人及 `ThreeSolo` 不擴充。

新增資格、未嘗試原因與逐相位顏色缺口；可選色子目標另列尚需幾色，不把其所有未消色都當必要色。新增原盤／換色／旋轉及系統案例仍待執行。形狀本身的 23.6.1 IDA 核對另見[規則對照](solver-native-rules-2026-11-07.md)，目前沒有已證實需要修正的標準盤精確形狀反例。完整待驗證清單見[開發紀錄](development.md)。
