# Solver 排序、取色快取與各形狀比較

2026-11-11。接續 Claude 中斷的審查與使用者核准的兩項實作。基準 commit `5d4448f`（0.5.44 交付紀錄）；本批包含稍後完成的九宮格優化，已獲授權進行 iOS 編譯測試。原始數據與來源雜湊見 [測量資料](../research/solver-policy-cache-20261111.json)。

## 已完成的來源變更

普通路線同時符合安全、必要目標及既有毒／荊棘排序後，仍先比較 Combo；相同 Combo 時優先選短路徑，最後才比較消珠量。Beam 仍按原引導保留候選，8P activity 維持原來的分數與 stepCost。普通、單次取色、離線 timed fishing 與連續取色的最終候選比較都使用相同政策。連續取色仍在找到第一條安全達標路線時結束，沒有因此延長搜尋以追求全域最短。

普通搜尋的提早停止条件相應更新：已達 Combo 的安全上界且其他更高優先条件也不可能改善時，更深、更長的原始路徑不會勝出；同一深度仍完整比較。保留取消及原時間上限。這是有限 beam 中的候選排序，不是最短路徑／最高傷害保證；同 Combo 可能少清一至兩顆，使用者已接受這個取捨。

連續取色使用與普通搜尋共用的 4096 格評分快取。每個 plan 換世代，完整色盤比較使 hash 碰撞只能降低命中率；同色交換也可命中。快取只含固定問題設定下的色盤評分，不含持珠位置、剩餘取色、交換歷史或完成許可。`goalsMet &= complete` 修改取出的副本。每次取色及最終原生輸入的限制維持現有程式。

Session 將實際評估次數與快取命中帶入所選路線、各次嘗試及總計。未返回路徑的多次取色嘗試仍可記錄評估數；`statisticsAvailable` 原本表示是否有可描述候選的語意不變，不能用快取命中來推論路徑可執行。

## 九宮格補搜：固定預算的獨立樣本

使用者要求九宮格也先最佳化再測試，本版已納入兩個互補方向。原搜尋及原有回溯都未找到安全達標路線時，才使用原期限內剩餘時間：第一輪每個缺口分配不同供珠，先處理最難到達的缺口；第二輪加重已填模板的進度、暫時不計相鄰珠修復成本。最多增加兩輪，每輪仍受原 beam、步數與取消條件限制；第一輪取得一半剩餘時間，第二輪用餘額，找到解就不開下一輪。

新增方向只適用於啟用 recovery、無轉轉、無荊棘、非 activity，且包含單組九宮格條件的普通搜尋；可與心四連等目標合用。引導不是可解性證明，最終仍按正式消除群組判定精確九顆、全部必要目標及安全，候選回到原評分尺度比較。診斷 `squareRecoveryPasses` 記錄這兩輪的實際使用數。

先在每情境 32 盤調整；直接取代原引導、供珠運輸代價及固定九宮位置的方案沒有穩定改善，因此未採用。確定上述兩方向後，另從種子 10000 開始取每情境前 96 個通過必要珠量檢查的盤面，與變更前來源依序跑；Thorough 48 步、beam 512，兩版同為 **800 ms**。合併正式來源後再次跑同一批，完整路徑／狀態／搜尋輪數與選定實驗版相同。

| 情境 | 成功數，補搜前→正式來源／96 | 每盤平均時間，前→正式來源 |
|---|---:|---:|
| 6×5 九宮格 | 88→94 | 78→87 ms |
| 6×5 九宮格＋心四連 | 53→71 | 192→303 ms |
| 7×6 九宮格 | 44→61 | 223→343 ms |

共補回 **41 盤**，逐盤零流失；原本成功的 **185 條完整路徑都相同**。正式來源成功的 226 盤全部通過獨立 Python 重播、首消形狀／心四連及消除判定；三版皆未逾時。額外搜尋提高成功率，也增加原本失敗盤的耗時，沒有宣稱求路更快。這批均為一般六色盤，不能推論 iPhone 速度、轉轉／荊棘盤或所有九宮格都可解；仍失敗的盤面沒有不可解證明。

[逐盤證據](../research/solver-square-recovery-20261111.json) 保存三版資料、來源雜湊、相對基準 commit 的實驗版差異，以及新解出的種子；[重跑程式](../research/orb_square_policy_probe.cpp) 的參數為盤數、完整情境名稱、起始種子。舊排序／快取 JSON 的來源雜湊刻意保留為當時快照，不冒充本次正式來源。

五次皆無方案逾時。兩版的完整路徑、取色交換、Combo、清珠數、候選數與方案數逐筆一致，並通過最後重播／目標／安全檢查。這是在此 Windows 桌機約減少 39% 時間的證據，不能承諾真機的 400 ms 分片一定成功。研究程式：[multi-cache probe](../research/orb_multi_cache_probe.cpp)。

## 審查結論與驗證狀態

有界 beam、bitboard、精確驗收與引導分離仍適合目前手機預算。此次共用評分快取可補上普通搜尋與多次取色的落差；三種搜尋的移動／交換狀態不同，沒有為了合併程式碼而重寫整個迴圈。跨深度去重先前實驗沒有穩定收益，未納入產品。九宮格補搜已納入並以獨立樣本驗證改善；其他形狀沿用已驗證的引導，不宣稱所有形狀已達最佳實作。

更正先前敘述：133 ms 的單次取色案例連舊版也會隨負載改變是否解出，不能据此歸因於 beam 排序。保存的無逾時形狀比較中，「只改最終排序」與「同時改 beam 排序」彙總一致；保留分開的政策是維護上的明確選擇。

本批合併九宮格後，Windows regression 與 private contract tests 通過。新增案例涵蓋安全／Combo／步數排序、activity 分數、Combo 上界早停、快取 hash 碰撞、跨方案隔離及取色完成標记。Windows 無 ASan/UBSan runtime，日誌裡的 `Sanitized solve tests` 在此只代表一般 smoke 執行。新增三個九宮格漏解回歸、獨立 oracle、禁用 recovery／取消與 spinner／thorn／activity 排除檢查。已收到「編譯測試」指示，Objective-C++ Session、macOS sanitizer、iPhoneOS 建置與 GUI 的最終結果見 [0.5.45 發布紀錄](release-0.5.45.md)；真機時序仍待裝置驗證。
