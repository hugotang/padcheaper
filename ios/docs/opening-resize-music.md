# 開場擴盤中斷與 BGM：0.5.9

2026-10-30，使用者回報 0.5.8 的開場只完成五步，連續模式在第 5 步技能期間停止，尚無轉珠輸入；另啟用未通關隊伍 BGM，但診斷顯示未找到曲目。使用者確認兩者都有，測試環境是 **Dopamine rootless 越獄的 iPhone 直接注入，沒有使用 LiveContainer**。新版 build 與真機狀態見 [開發紀錄](development.md)。

## 開場

已確認順序是五格武裝 → 雨龍變身 → 四格武裝 → 二格武裝 → 三格武裝；第五個 native 使用次數由 4 到 5，已停止的 session 之後才補記確認，第六步未嘗試。沒有當時逐幀讀取資料，舊 log 無法證明是哪一個指標或座標校驗失敗。

技能資料 63581 的子技能 63582 為 native type 244、參數 `[3,1]`，將盤面改成 7×6 三回合。IDA dispatcher `0x1005C5DF0` case 244 呼叫 `0x1005C5D18`，再由 `0x10055B6B4` 設定 `impl+752660` 的 0→1 插值。`0x1005AB350` 在進度到 1 後才提交新尺寸、重排格心及清插值；battle phase 可能仍是 2。0.5.8 只依 phase 決定是否要求完整等距珠子座標，會把這種過渡幾何當成不可讀。

0.5.9 讀取已查證的插值，非有限數值或超出 0–1 仍拒絕。進度不同於目標、或進度已達 1 尚待提交時，只發布再次核對的戰鬥身分、階段、輸入和技能資料；不跟隨盤面 token，標示盤面不穩定、技能 busy、未知珠數。開場保留已啟動技能與原生使用次數，回到完整穩定盤面後核對角色／武裝及次數，再啟動下一步。這不是對任意讀取失敗的重試。

所有實際施放、求路和轉珠仍要求完整快照。手指、離場、帳號／hash／輸入 manager 改變、多人、保護值失敗或 30 秒技能等候逾時仍停止。手動停止後只觀察已啟動技能，恢復連續模式才繼續未執行的步驟。`Orb board transition` 與 `Orb last read issue` 保留動畫及失敗原因，後續普通讀盤不抹掉它。

## BGM

IDA `0x1004EED4C` 直接註冊 native 靜態表 1029 個曲目名稱；`audio+16/+24` 是註冊表／數量，不能據此宣稱音訊檔案已載入。原表名稱如 `bgm_972.caf`。原生 selector `0x1005A4D8C` 讀 descriptor 的道中／頭目名稱，交給 `0x1004EEDD4`，後者以 `0x100235674` **忽略 ASCII 大小寫、比較非空指定前綴、採第一個匹配項目**。0.5.8 的 NSString 完全相等比對不等價，會錯過沒有副檔名或大小寫不同的 descriptor。

0.5.9 複製該比對規則，不自造檔名、不盲目加載音訊。表位址／數量、完整條目與匹配次序核對後才使用 native override setter；同表快取只適用於不可寫名稱，表重排或名稱可變時重新掃描。未找到時列所選隊伍、encoded／descriptor ID、requested 名稱與註冊數量；成功列 registered 名稱與 track index。舊 log 沒有名稱，這是已確認的實作缺陷，是否完全解決該裝置曲目仍需新版 log 與播放結果。

未通關條件只讀、不改 clear flag；多人、固定隊伍／特殊關卡、隨機 RND 排除與 native event 讓權沿用。找不到資源或 native setter 未能讀回確認時不反覆改寫。

## 回歸範圍

新增真實佈局 native fixture 檢查 phase 2 的擴盤、progress 1 的最後幀、損壞 token 不跟隨、保護值／插值錯誤、身分競態及多人拒絕。完整六步 session 模擬第 5 步擴盤，驗證 7×6 穩定後才第 6 步、停止／恢復不重播，以及逾時、前景、手指、離場、hash、多人與讀取失敗。

BGM fixture 驗證 descriptor 無 `.caf`、大小寫、前綴碰撞的 native 首項次序、可變名稱與表重排、查找途中換表或原地重排、空名／非前綴拒絕及既有讓權／還原／單人條件。這些替身回歸不能驗證 Dopamine 音訊或實際技能演出；不可把新增案例當成已通過，執行結果另記。
