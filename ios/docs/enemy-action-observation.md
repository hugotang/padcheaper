# 敵人行動定義與目前 AI 狀態

2026-11-01，**源碼與案例已寫，尚未編譯、執行測試或真機驗證**。0.5.14 不含本批。[完整設計](enemy-aware-automation.md) 的下一擊／減傷／回血和 L＋心四連耐久仍未開放。本批先取得可供後續核對的原生定義，不改必要救援、技能使用、求路或輸入授權。

## 本批輸出

穩定普通單人盤面的 `battleObservation.enemyActions` 保存最多八個敵人：實際 catalog ID／參數索引、目前 HP／上限、未乘憤怒的攻擊值、攻擊屬性、原生倒數、level、AI 旗標／計數／行動數／budget、快取選招／複合進度、憤怒及其他尚未完全建模的 override 原值。來源參數以實際 ID 和原生鏈結查找核對，特殊版本不能借相同圖鑑號的普通行動表。

每隻敵人的 64 列全部讀取；中間零 ID 只跳過該列，不提早結束。非零列保留位置、ID 和四個原始運算元；完整 512 bytes 另以 hex 保留，包含空列中的其他值。行動紀錄為 72 bytes，保留 opcode、八個 signed parameters、機率／HP／budget 欄位、附帶攻擊比例和原始 hex／SHA-256。原生表頭 format／version／count／checksum 保留 raw；沒有執行全表 checksum，不能把該欄位當已驗證的內容證明。沒有讀取行動文字池、帳號或封包，也不輸出程序指標。

| 欄位 | 意義 |
| --- | --- |
| `status=ready` | 本次有界雙讀及目前窗口核對通過；個別敵人／定義仍可未知 |
| `rawCaptureComplete` | 本批選定欄位、全部列及可識別引用已完整收集，沒有超限或無法讀取；不代表所有 opcode 的其他語意／引用都已支援 |
| `definitionCaptureComplete`／`structureSupported` | 上述收集完整，且本批辨識的結構沒有未知 opcode、循環、巢狀複合或非法跳轉 |
| `enemyForecastKnown`／`actionReachabilityKnown` | 本版固定 false；沒有模擬選招或證明下一回合可達集合 |
| `damageBoundKnown`／`survivalKnown` | 本版固定 false；原始攻擊數字不是下一擊傷害 |
| `spawnIdentityKnown`／`nextFloorKnown` | 本版固定 false；沒有跨取樣的 spawn 世代或未生成樓層資料 |

詳細頁顯示已讀定義數與未完整／未支援狀態；下一回合可達招式仍顯示未判定。這份資料在整體 observation 失效時一起撤下；只有敵人新讀取失敗時，不保留前一份行動表，較早的獨立 L／CD 診斷及既有求路仍可使用。不同取樣之間可能已發生變化，不能借診斷快取授權下一步。

## 結構解析與明確限制

純 C++ 解析器 `PHEnemyActions.h` 只處理定義，不執行條件。已辨識部分一次旗標、旗標設定／清除／OR／XOR、計數、HP／level／計數比較、跳轉與 selector pass 結束。保留原始運算元；原生兩種跳轉的目的列基準不同，分別記錄，非法目的列不截成合法值。HP 條件目前只是描述，沒有以消珠前 HP 排除低血分支。

opcode 83 複合行動保留第一個非正數前的子 ID 次序，包括重複 ID。全部八個 raw parameters 仍可核對。子定義共用查找去重，巢狀複合和循環明示未知；八個子 ID 全正數也標成 `unterminated-compound`，因原生四位元 index 未證明在第八個子招後停止，不能自行假定後面的 weight 欄位永不被解讀。

opcode 88／141 分別標為覺醒無效／武裝無效。這是效果種類的識別，沒有完整效果模擬；正的 +68 附帶攻擊比例保留「先攻擊再效果」關係。其他 opcode（包括尚未核對的普通攻擊、連擊、禁消、延遲及 type 82 fallback）保留 unknown，沒有給零傷害。普通綁定 1／2／3 不能當普通攻擊。

兩種原生選招器會更新旗標、計數、budget 和 RNG，也涉及 HP、其他敵人選招、盤面／隊伍、能力可用性與特殊模式。**程式不呼叫它們**，不把 selected/pending cached ID 當「下一招」。空行動表可能走普通攻擊 fallback；倒數 1 尚未證明下次具體攻擊時序。當前攻擊會再乘憤怒、附加值及多層減傷並逐層取整；本批不計算它們的合併結果。

原始定義雜湊用於對照，不是 spawn 身分。只以本次入場／wave／實際參數及前後雙讀防止混用；尚未建立跨回合的敵人世代、完全重生判定或下一層先制快取。

## 讀取與隔離

沿用既有約 0.75 秒取樣與 1.5 秒資料年齡限制，只有較早戰況診斷的穩定窗口成立才收集。行動資料用獨立的 dictionary 保存，不擴大每幀及求路複製的 `PHOrbSnapshot`。敵人表另設 32 組可選指紋，與 114 組操作、15 組先前診斷和 45 組 L 政策指紋隔離；本組失配不阻止原有功能。

每次最多兩遍，每遍共用 192 筆 action、深度 8、128 KiB／256 次資料 block 讀取預算；包含敵人與 catalog 鏈，不為每隻敵人重設。表頭、既有窗口／隊員讀取、32 組指紋及最後一次盤面核對另計，`readBytes`／`readCalls` 是其中一遍資料收集的計數，並非整次診斷成本或耗時保證。正式的 `readDurationMS` 包含先前觀察與新行動讀取；實機成本仍待量測。

兩次收集比較解碼後選定值與原始行動紀錄，重查 catalog／action 表來源、表頭、entry、key、phase、wave、moves、持珠／手指、盤面／隊長。與同批較早觀察的敵人 HP／parts 亦交叉檢查。保護失敗或變動回傳空的失效狀態；未知單欄資料保留 known 標記，不把未讀值當零。遊戲主執行緒雙讀並不是原子快照。

3／4／8 人與 3 人單人續玩不啟用。原有多人明確轉一次的例外不擴張。沒有新增 config、預放解覺醒、延後 required、撤掉光 T 或自動 L＋心四耐久。
