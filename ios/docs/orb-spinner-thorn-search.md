當次目標都是首消光 T 一組及心四連一組、6×5、六色共用相位轉轉；前三盤另有 4% 刺珠。四份 log 的停止盤、當次 HP／有效上限／待結算傷害及十個不同的已執行回合，保存於 [去識別盤面資料](../research/orb-shape-thorn-20261030.json)。較早已執行回合沒有其當時 HP，不能借用最後停止盤的 HP 驗證存活。

第一盘的證明故意放寬即時逆走、48 步上限、非光珠互換及心四連要求，但仍保持原生目標刺珠傷害和四方向／避轉轉規則。第一個接觸後，該刺珠被換到上一格；再次進入會超出一次接觸預算，因此在抽象模型中成為新阻擋格。抓起刺珠本身不算接觸，持珠 token 隨每步移動，其他刺珠仍在各自格子。每個起點的去重圖全部遍歷完成，並檢查轉轉是光及非光兩種必要相位；零 T 結論是這套模型的證明，不是任意遊戲玩法都無解。

第三盤的枚舉先使用「轉轉非光時仍須有固定光 T」這個必要條件，遍歷所有五格 T、額外第六顆固定光，排除轉轉格並去重，共 816 個相關放手配置。其餘固定格全部是心，各配置以獨立標記／連通群組／重力 oracle 驗證六相位。沒有 T 的配置由必要條件排除；包含 T 的配置沒有漏掉。這不是「心太多必然無解」的一般定理，也不涵蓋從轉轉換出不同珠色之後的盤面。

兩份完整探針和正式結果見 [低血圖](../research/orb_lowhp_reachability_probe.cpp)、[高心配置枚舉](../research/orb_dense_heart_probe.cpp) 及 [可行性結果](../research/orb-shape-thorn-feasibility-0510.json)。探針只用於離線研究，沒有接入 dylib 或每幀執行。

## 0.5.10 求路修正與量測

中途有刺珠接觸但尚未排出心四連的候選，可以留在搜尋中繼續修補。每次更新最終最佳路徑，仍核對完整心四連／傷害／毒／爆彈政策；這個改動只作用於中間排序，未完成心四連的路線仍不可執行。多相位轉轉、刺珠及兩項以上形狀目標同時出現時，主搜尋額外重視最耗珠的精確形狀；四連、整橫排及整直行不作此重點。這是一般目標選擇，不含裝置盤面或見證路徑的硬編碼。

消除評估改以位元集合計算已標記直線及連通群組，重力後重建各色集合。最少直線／連通群組、不可消、首消形狀、T 保守外緣、實際四連群組、共用轉轉相位及毒／爆彈限制仍使用原有語意。回復 pass、最多兩批回訪、零接觸補搜及總搜尋期限保持共用。

使用同一獨立 probe、每份停止盤原本的 HP 和已開啟的刺珠 Combo 偏好，0.5.9 與候選版交錯執行，每盤各三次，合計 24 次。所有路徑、每次目標刺珠交換、全部六相位 T／四連／Combo／重力及最終存活 gate 均通過獨立 oracle，完整 [輸入及結果](../research/orb-shape-thorn-results-0510.json) 保存正規化來源及探針雜湊。

第二盤舊版 0／3 次達標、800 ms；候選版 3／3 次達標，中位數 318 ms，45 步、最低 5 Combo、15 次接觸、傷害上限 418,695。其餘盤保留前述拒絕，不宣稱全數停止問題已修復。桌面時間不代表 iPhone 效能。30 fps 時每步 `ceil(0.065×30)/30 = 2/30` 秒，45 步加 0.4 秒餘裕約 3.4 秒；仍須在執行前由原生剩餘時間及 4 秒上限核對，不能假設每次都可走完整路線。

一般盤及截圖新舊共 456 次交錯對照，全部獨立 oracle 通過，原成功案例沒有退步。36 個一般盤心四連三檔維持 30／33／36 次達標，候選版中位數 10.3／23.9／68.1 ms，基準為 12.4／29.6／81.0 ms；心連消至少四珠維持 25／29／34。完整 [一般盤結果](../research/orb-shape-results-0510.json) 保留全部測量。

## diagonal 與轉轉取色的建議

建議先比較少量 diagonal 補搜，再做只補一顆的轉轉起手；尚未在 0.5.10 啟用這兩種新輸入策略。

原生 `0x100608968` 在 game `+93 == 1` 時允許 `abs(dx)==abs(dy)`，並在迴圈中同時加減 x／y後呼叫 `0x100608738` 交換兩個 token；相鄰斜格可以是一個直接交換。`+93` 即讀盤的 `freeMovement`，正式 ordinary gate 已要求它為 1。這是 diagonal 的靜態依據；仍須核對原生最近珠選取、每幀座標、交換計數、實際 token 及刺珠傷害後才能投入執行。若原生接到不同目標，不能用理論斜步的預覽放行。

八方向擴大可達配置，也可能縮短路徑、繞過原四方向必碰的刺珠；但分支最多由 4 變 8，固定 800 ms 內未必能搜得更深。可先保留四方向結果，再以共用餘裕作少量斜步補搜並量測。消除仍是橫／直直線及四方向連通，不能把盤面消除的鄰接關係一起改成八方向。第一盤的四方向可達性證據不適用 diagonal；第三盤的配置衝突及第四盤的缺心證據仍適用單純換位。

轉轉取色第一階段宜只處理「少一顆」：離手時等到指定色，從該轉轉起手，把所抓珠帶出，确认原生實際顏色後接預先核對的普通路徑。原生 `0x1005AB350` 只在 block `+18 == 0`、未鎖定時變色，`0x10060D1F0` 選珠後把持有 token 的 state 設為 4；交換改目標 state 為 3，持有 token 不在該次交換中被改成 0。這支持持珠期間保色，但未涵蓋每種後續狀態、取色與 native hook 的幀次序、spinner 留在原格的更新，以及放手前的總時間，尚未以真機證實。

缺心要等心、缺光才等光；取出一顆會把原格的普通珠換回轉轉位置，後續相位及首消仍須重算。求路前等待且未選珠通常尚未開始移動計時，選珠後再背景求路則會用掉時間；可靠實作宜先求出指定取色後的路徑，接受起點時確認實際顏色，偏離便停止。珠太多時換走某色、途中多次取色／停等、精確放手相位，需要更完整時間與盤面模型，應在單顆補珠可靠之後再比較。
