# 六人編隊與入口設定

`0.4.5-solo`；日服 PAD 23.6.0／106878。戰鬥套隊與數值寫入僅限單人。使用者回報多人只有本機隊伍顯示改變、數值不同步及斷線，因此移除多人入場套用與同步補回。先前 host 看見替換不代表其他玩家、實際數值或結算一致。

單人入場保留初始 SB、有效最大 HP 初始化與原生隊伍刷新。使用者已確認單人套隊／SB 成功，新版 HP 仍需真機核對。詳見 [入場數值與時機](entry-derived-state.md)。

## 編輯與使用

1. 點 PC →「編輯六人隊伍」。上排六格武裝與下排六格本體，分別對應位置 1–6；第六格為助人。
2. 點選一格，搜尋遊戲圖鑑編號或角色名稱。輸入使用遊戲內圖鑑號，#9900 起在原生邊界加 100；#14238 猫猫使用內部 ID 14338。
3. 調整本體／武裝各自的等級、技能等級和普通覺醒。本體另可選超覺醒／潛覺；超覺醒依該角色可用項目、等級及加值檢查。
4. 預設本體採角色最高等級（可限界突破時 Lv.120）、普通覺醒全開、+891。武裝預設最高 Lv.99、普通覺醒全開、+297、SLv.1；可另行修改。滿技與現有技能充能是不同設定。
5.「貼上隊伍」讀取剪貼簿中的日服 PADDashFormation v2–v5 單人分享連結或 JSON。「複製分享連結」可回到 PADDashFormation 開啟；徽章、入場後隊長交換及關卡倍率不屬於這份角色配方，匯入後會提示另行設定。
6.「儲存隊伍」或「完成」保存目前選取的隊伍。「套用本格／整隊」先驗證全部選定配方，再於遊戲 frame 逐格執行；每 frame 最多一筆原生操作。某格失敗時取消後續位置，成功位置保留還原紀錄。手動套用保留現有充能，並依新角色上限裁切。
7. 在單人戰鬥中，「還原本格」只恢復該位置，「全部還原／取消」取消尚未執行項目並逐格還原。關閉總開關或縮小入口允許清單，也會在相同戰鬥的可操作階段還原。

角色資料、搜尋、51 種潛覺名稱、153 種普通／超覺醒名稱與分享資料解析內建於 dylib，可離線使用；頭像從 PADDashFormation 的公開圖鑑圖集載入，需要連線。未知潛覺 ID 仍可保留，但不放進新增選單。戰鬥圖片、技能、音訊及效果仍由遊戲提供。輸入欄位字體至少 16px，避免 iOS 喚出鍵盤時自動放大。原快速本體替換區已移除。

## 多隊伍儲存

編隊頁上方的「隊伍庫」可選取最多 64 個隊伍。切換或新增前會儲存目前編輯；「另存新隊」複製目前編輯為獨立隊伍，保留原隊伍先前的儲存內容。「刪除隊伍」需在頁內確認，至少保留一隊。改名使用隊伍名稱欄位。

隊伍庫與目前選取項目保存在 guest 容器的 `Library/Application Support/PADHelper/formations.json`。首次更新會把有效的舊 formation.json 轉入隊伍庫，並繼續把目前選取隊伍寫入 formation.json 作備份。重新啟動會載入整個隊伍庫及選取項目。儲存隊伍只更新設定，戰鬥還原紀錄則只保留於目前程序／地下城。

## 入場自動套隊與 SB

1. 在地下城外編好並儲存隊伍，確認隊伍庫選中要使用的一隊。
2. 在 PC 面板開啟總開關、「戰鬥隊員替換」及「入場自動套用隊伍」。此選項預設關閉，保存在 `battle.autoApplyTeam`。
3. 下次單人新入場時，在 wave 0 的開場動畫、敵人先制前一次套用整批配方。空白本體位置保留原隊員。
4. 使用新隊伍的原生覺醒、潛覺及徽章計數重算初始 SB，再由原生充能函式處理技能上限及關卡限制；面板顯示本次 SB 與自動套用結果。

中途開啟選項會等下次入場，恢復中的地下城與後續樓層不重算充能。套隊失敗會嘗試回復原隊伍、HP 與原入場充能；若無法確認完整回復，停止後續操作並顯示原因。選取隊伍在入場時固定，開場期間更改設定不會替換已排程的配方。不要以技能滿級等同技能已充滿：先制延遲等後續效果仍由遊戲處理。

多人戰鬥不會套用、補回、還原、重算 SB／HP 或干預計時；一旦偵測多人，就取消待執行項目並維持停用至離開本場。不會嘗試把舊隊伍寫回多人戰鬥。編輯／儲存隊伍庫仍可使用，留待下次單人入場。

診斷新增 `Battle writes: single-player only / multiplayer disabled`。多人下的 digest 未計算、隊員列表未讀取屬預期行為，不能解讀成原生校驗失敗或隊員消失。

## GUI／config 的入口過濾

PC →「單人入口設定」顯示目前 mode／source／multi。mode／source 各有「全部允許」開關；關閉後可點清單輸入整數，以逗號分隔。變更自動存到遊戲 guest 容器的 `Library/Application Support/PADHelper/config.json`，每秒重載，無需重新編譯或重新啟動。

| config 的 battle 欄位 | 預設 | 用途 |
|---|---|---|
| allowAllModes / entryModes | true / [0,1,12] | 開啟時不限制入口分類；關閉時採指定清單 |
| allowAllSources / sourceModes | false / [0] | 過濾遊戲的隊員資料來源 |
| allowAllMulti / multiModes | false / [0] | 舊設定相容欄位；不能解除多人停用 |
| autoApplyTeam | false | 下次單人新入場使用選取隊伍並初始化 SB／HP |

```json
"battle": {
  "allowAllModes": true,
  "entryModes": [0, 1, 12],
  "allowAllSources": false,
  "sourceModes": [0],
  "allowAllMulti": false,
  "multiModes": [0],
  "autoApplyTeam": false
}
```

每份清單最多 32 個不重複的非負整數。mode／source 上限 65535，multi 上限 4294967295。空清單且未開全部允許時停止新操作；既有成功替換會使用已驗證的交易設定還原。開啟全部允許不刪除原清單。舊 schema 1 的 config 可直接使用，缺少 battle 時採上述預設。

這些設定只改過濾規則，不改寫遊戲的 mode／source／multi。非零 multi 及 mode 7 永遠不可寫入，即使設定清單明確列出或 `allowAllMulti` 為 true 也不例外。單人仍須通過版本、指令、記憶體範圍、輸入、HP／摘要及腳本參數檢查。

## 原生參數來源與驗收

完整配方使用十個原生 44-byte 腳本參數槽中的空閒記錄；最多六個獨立租用。一般地下城沒有腳本時，用原生 allocator 的正確 category／tag 建立有效的空 bytecode，沒有事件入口或執行中的 runner 才發布。已有事件、敵人腳本條件不相容、參數被占用或 ownership 不符時跳過。最後一次還原先解除引用，確認後才釋放；遊戲接管／換場景後不釋放快取指標。

不寫帳號持有卡片記錄，也不產生可執行記憶體。租用按來源、參數槽與唯一 token 追蹤，隊長交換或普通原生變身後仍可找回；還原保留當時充能並裁切到原角色上限。失敗處理保留原生異常旗標，無法確認回復就停止後續寫入。

測試保留單人六組配方、武裝、超／潛覺、全批次預驗證、手動逐 frame 操作、一次性 SB／HP、恢復／後續樓層排除及故障還原。新增多人零 native call／零寫入測試，包含 host／guest、舊 allow-all、過期單人快照、取消排程、還原、原生呼叫途中轉多人及離場後恢復單人功能。模擬器檢查編隊庫、輸入縮放、設定保存、重啟與 scene／legacy 視窗。這些不代表真機多人同步或伺服器結算已通過。
