# HP 自救、我方異常與必要技能

`0.5.1-orbs` 第五批源碼。尚未編譯、執行測試套件或真機驗證；依分批開發約定，收到「編譯測試」後才集中建置。

第六批另加入 [低血時的心珠目標](orb-recovery.md)：技能後仍低血時，可要求實際消除指定組數的心珠；不取代這裡的必要技能確認。

## 新條件

「編輯自動技能規則」新增三個可選欄位，會與技能規則一併存入目前策略。舊設定維持原有行為。

| 欄位 | 預設 | 行為 |
|---|---|---|
| `hpAtMost` | 0 | 0 不限定；1–100 表示目前 HP 不超過有效上限的指定百分比，包含等於門檻 |
| `status` | `none` | 不限定，或 `awoken_bind` 暫時覺醒無效、`member_bind` 任一有效隊員被綁定、`skill_seal` 技能封印 |
| `required` | false | 條件仍成立而未確認技能完成時，停止自動轉珠；不直接略過 |

同一條規則的條件仍取交集。例如同時填 HP 40% 及暫時覺醒無效，必須兩者都成立；若希望任一情況都處理，請分成兩條規則。角色編號限制仍比對當前形態，變身後不符合編號時不觸發該條規則。

HP 使用目前有效上限，包含固定 HP、關卡比例、臨時固定上限及臨時比例上限。比較採整數交叉乘法，不會把 40.1% 四捨五入後判成不超過 40%。介面的一位小數只是顯示。

需要判斷 HP 條件但 HP 或上限無法確認時，規則會停止；沒有 HP 條件的舊規則仍可按原有資料判斷。一般規則若已因隊員不可用、保留樓層或使用紀錄而略過，不要求額外的條件資料；必要規則仍須確認觸發條件，資料未知時停止。暫時覺醒無效和關卡本身禁止覺醒分開顯示；後者本身不觸發解覺醒技能。隊員綁定條件檢查全隊，但施放者本身被綁定時仍不能施放。技能封印條件可用於必要規則的停止提示，不代表能在封印中強制施放技能。

下面是一份包含兩條獨立救援規則的設定片段。位置和技能由使用者按實際隊伍指定，程式不自動判斷哪個角色能回血或解除異常。

```json
[
  {"enabled": true, "slot": 2, "monster": 0, "every": 1, "floor": 0,
   "color": -1, "below": 0, "enemy": "none",
   "hpAtMost": 40, "status": "none", "required": true},
  {"enabled": true, "slot": 3, "monster": 0, "every": 1, "floor": 0,
   "color": -1, "below": 0, "enemy": "none",
   "hpAtMost": 0, "status": "awoken_bind", "required": true}
]
```

不可消仍使用既有 `obstacle: "unmatchable"`，也可加上 `required: true`。不同必要技能使用獨立規則或不同輪替組。

## 必要技能的完成條件

不可用的必要技能不會立即阻止其他規則。系統先讓剩餘技能或同組替補嘗試；技能完成後重新讀取 HP、我方異常和盤面，重新判斷。例如後面的回血技能已讓 HP 高於門檻，原先缺乏冷卻的救援技能便不再是必要；加速也可能使它重新可用。

準備求路前，所有仍觸發的必要規則都必須滿足以下之一：

- 該條規則本回合已有原生施放及完成確認。
- 該規則所屬輪替組本回合已有一個技能完成確認。組內成員被視為替代選擇。

否則停止並顯示未完成的規則及原因，例如冷卻不足、施放者綁定、手動技能選項、保留樓層、一次性紀錄已用完、同位置已使用，或啟動後未確認完成。必要設定不會越過這些限制。

「已嘗試」和「已確認完成」分開記錄。原生啟動結果不確定，或使用者在技能完成確認前停止，都不會在重新開始後被當成成功，也不會為了補確認而重複施放。兩種紀錄都跨停止保留；確認下一個轉珠回合後才清除每回合紀錄。修改執行規則不能讓舊規則的完成紀錄滿足新的必要要求。

一次性必要規則若在後續回合仍符合條件，會因不能再次使用而停止；請搭配變身前角色編號或適當條件。技能確認完成只代表遊戲接受並完成施放，不保證已回到 HP 門檻、解除所有異常或能承受敵人攻擊。這批沒有完整傷害、回復量或斬殺模型。

## 判斷顯示與舊決策取消

轉珠頁顯示自動模式當前讀到的 HP／上限、已支援的我方狀態，以及最近一輪逐條規則判斷。未觸發、已完成、等待替補和停止原因會分別說明；近期事件保留技能觸發及完成紀錄。停止後的規則判斷是最近紀錄，並非背景持續計算出的新策略。

有 HP、我方異常或必要規則時，求路至執行期間若 HP、有效上限或我方異常變化，舊決策取消。已按下或交換珠子時仍走既有放開流程；不讓新出現的救援條件沿用舊路徑。仍只支援單人，不自動進場、續關、重開或恢復已停止的連續模式。

## 靜態依據與範圍

目標仍為日服 23.6.0／106878。以下來自原始 IPA 的 IDA 對照；讀取實作不呼叫 HP、冷卻或覺醒 getter，也不寫入 HP、效果或冷卻。

| 依據 | 用途 |
|---|---|
| `0x1005FB690` | 原生有效最大 HP；controller 為 `impl +0xB3590` |
| `impl +0xB7E10 / +0xB7E20` | 受保護的基礎 HP 低／高 32 位；三份解碼必須一致 |
| `impl +0xB7E38 / +0xB7EE4` | 當前 HP 與 XOR 鏡像；鏡像常數 `0x8085A6BE` |
| `impl +0xB480C / +0xB4810` | 臨時 HP 上限持續時間及受保護參數 |
| `0x10023F7C0 / 0x10023E524 / 0x10023E670` | 關卡 `hpfix:` 與 `hpper:`；前者優先，各取首個對應項目 |
| `0x100047AE0 / 0x1000480E0` | 非負 HP 的 float32／float64 加 0.5 後取整；臨時比例路徑上限常數核對為 `2147483647.0` |
| `0x10059F2BC` | 暫時覺醒無效在 `impl +0xB465C`；關卡指標 `impl +0xB0F20` 的 `+33` bit 2 為固定覺醒限制 |

關卡選項最多讀 8192 bytes，要求有結尾、可讀 ASCII 及有效非負整數 HP 參數。原生寬鬆 `atoi` 可接受的畸形字串不當成可靠資料；未知格式、無效保護值、鏡像不符或不支援的 HP 範圍會標成未知。關卡比例保留 float32 計算，臨時比例保留 float64、最低 1 與有號 32 位上限。

目標檔新增五筆 64-byte 程式指紋，合計 26 筆。新 HP 欄位只由明確啟用的自動模式讀取；一般預覽維持原有讀取流程。

待集中驗證：HP 門檻及溢位邊界、固定／比例上限、狀態到期、未知資料、冷卻／綁定／封技／保留衝突、加速與替補、未確認施放跨停止、HP 在求路或原生輸入當幀改變、設定／策略同步保存，以及 GUI 數字鍵盤、失敗草稿、成功回讀和判斷顯示。真機另驗不同 HP 關卡、複合／變身技能及每 frame 讀取成本。
