# B2 不可消回復：原生依據與支援界線

2026-11-19，0.5.57 已通過 Windows 可攜回歸及 [CI 184](https://github.com/hugotang/padcheaper/actions/runs/44531845996) 完整編譯測試並交付，完成證據見交付包 `verification.json`。實機驗證仍未完成。對應 `coral-fixed-585607-v90-r5`；既有 0.5.56／r4 交付不含此能力。

GameWith 的 B2 主線仍為六色無四顆存一回，再用 Atori 收尾。AppMedia 明列巴索羅繆不可消時以火／木四連回復；兩站敵人資料列出半血後隨機一色不可消一回合。裝置 log 確認半血、闇不可消及 Solomon 尚差兩回合，沒有證明前盤四顆違規。r5 採用這個機制分支，不插入技能或額外存技回合。[裝置摘要](../research/coral-b2-unmatchable-20261119.json)保存最小化資料。

靜態分析使用 23.6.1／107553 的原始 arm64 可執行檔，SHA-256 為 `3ac8c5647e67694b5a3e68cf7049d3860f82f029a7e67f96477e9e2a3f490fd6`；未修改二進位、資料庫或執行遊戲函式。[分析收據](../research/unmatchable-recovery-20261119.json)保存函式雜湊與政策專用的 64-byte 指紋。

`readUnmatchableRecovery` 沿用獨立的唯讀來源收集，改讀不可消回合／遮罩、潛覺 41 與 TPA 權重。兩次收集都須一致，且重核對戰鬥身分、catalog、保護金鑰、隊員來源、phase、moves、持珠及空佇列；動態覺醒授予等尚未核對的來源不會提供回復額度。原生碼指紋只在此政策啟用時驗證，失配即停止該政策。

目前只接受單人 B2、唯一存活普通敵人 `200974`、一種基本色不可消一回合、正常三珠匹配，以及不含特殊珠／荊棘／釘珠／Combo 珠的盤面。只把原生掃描的**第一個實際組**視為可授權回復的組：必須為孤立、正好四顆的合資格火或木，並排除相連但未列入消除的珠。這個保守限制避開後續組的佇列競爭；它不代表已證明所有原生特效的佇列容量。所有新分支仍需裝置驗證。

求解保留第一批的真實五色與心珠計數，第一組回復後才允許受阻色參與後續落下消除；六色與受阻心四都必須在既有珠的模擬中成立。普通轉轉路線逐共同相位重播，任何一相位失敗即拒絕。單次／連續 fishing API 及 Session 均拒絕此政策；首批加算 Combo 契約也暫不混用。已存在的毒珠／荊棘首消心條件不受後續心四影響。

求路與預覽每 0.25 秒重新收集提供者；起手、持珠與原生座標轉換後輸入邊界再次核對。改變會撤銷舊路線，仍保留已持有珠的清理放手。回合後須觀察不可消回合與遮罩均為零，並把結果綁定同一 generation、turn、戰鬥與放手紀錄。自然倒數、敵人重施與潛覺回復不能只靠該樣本區分，故 `actualConfirmed` 只表示觀察到清除，`latentOnlyAmountConfirmed` 始終為 false。

求解器、schema、原生讀取／輸入與 Session 回歸、sanitizers、iPhoneOS 及 GUI 已通過 CI 184。真機仍須核對回復動畫與下一批消除的先後、所有轉轉相位、原 B2 盤面能否在手機預算內找到路線，以及實際傷害／通關。模擬不預測天降，沒有保證擊殺或存活；B15 多色不可消仍使用既有 Solomon 路線。
