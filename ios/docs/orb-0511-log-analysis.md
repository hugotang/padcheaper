畫面隊長／助人均為上弦之貳・童磨 #12832。現有隊長資料對應 skill 56172，解析為水至少五珠連消，以及五種攻擊色之一的十字。最新 generation 63 的 `goals` 正是這兩項，獨立盤面 oracle 確認首消水十字格子 `[1,6,7,8,13]`（由上到下、由左到右、零起算），同一組五顆同時滿足兩個目標。

## 第三份：缺心與技能窗口是不同問題

最新 6×5 的底行六顆轉轉不供固定路徑移入；其餘固定六色數為 `[5,2,5,7,3,2]`。心珠在所有共用相位的最低值為 2，無法保證首消直線心四連，所以缺珠檢查即時停止，不是 800 ms 搜尋超時，也不是刺珠／一般毒判斷擋住路徑。

最近技能決策捕獲 `window 0 / busy 0`，較晚面板則為 `window 1`。夜一位置 2 的充能 4、白哉位置 6 的充能 2，單靠充能數字不足以證明可用；使用者確認兩者停止後立即可手動施放，進一步支持短暫窗口被快取為本回合不可用的問題。舊 log 缺少各 gate 的原生原因，尚不能證明確切是哪個條件或哪一幀造成關閉。

本次連續模式記錄為 7 次轉珠、9 次技能，程序累積完成 9 次。開場六步已 6／6。

## 第一份：現行六相位 T 模型下無配置

轉轉的一基座標為 `(2,3),(2,4),(2,5),(5,3),(5,4),(5,5)`，mask `7516196352`，固定六色數 `[4,5,7,8,6,6]`。

獨立配置分析放寬至「所有固定格珠子任意重排」，保持光珠 8 顆、六格轉轉位置及共用相位；每個相位可選不同的首消光 T，但固定格配置必須相同。先忽略手指路徑、心四連、刺珠與步數，以檢查較寬鬆情況是否仍能配置。

現行 T 規則要求五顆 T 及其橫直外緣沒有同色珠。80 個幾何 T 模板中，20 個不占轉轉格，沒有任何一個連外緣也完全避開轉轉。六相位各自可行模板數為 `[23,20,23,22,20,21]`；合併光珠必占／禁占格後，兼容狀態依次剩 `[23,18,16,11,11,0]`。另一個精確光珠數的遞迴枚舉走過 80 個節點，結果同樣無配置。

因此，現行「相同固定配置＋全部共用相位＋保守 T 外緣」政策下，diagonal 或延長搜尋時間無法修好這盤。這個結論不涵蓋定時抓取轉轉顏色、移入轉轉改色，或改變 T 邊界語意的其他模型；沒有主張遊戲中的所有手動策略都無解。本批不更改這些模型。

第一份最近候選未開始，前一次成功歷史已 34／34 步、2368 ms、最低 7 Combo、兩項皆達成且放開確認。歷史的心四連消一般毒政策為 false，最新為 true，表示不同時點捕獲設定，不能混讀。

## 源碼修正與 diagonal 時機

本批源碼已將「窗口關閉、未呼叫原生」與「真正嘗試後原生判定不可用」分開。短暫窗口關閉先等最多 3 秒、重新取得穩定快照；不消耗 once／輪替組，不開始轉珠。求路後、首次觸碰前窗口關閉也作廢路徑並回到技能判斷。窗口以外的 HP、場景、隊員、操作等變化仍不能當作這個重試例外。

已知封印、技能次數限制、關卡／教學及未支援敵人部位保留既有規則限制；必要技能或未完成開場不能被略過。真正原生拒絕仍沿用本回合快取；技能確認完成後才保留既有加速重查行為。

新診斷保存搜尋／歷史的隊長、目標模式、continuous／once／preview 用途，以及技能窗口原因；停止後讀取失敗不覆蓋成功歷史。保留資料會標明目前是否可讀、是否同一戰鬥，技能決策也比較捕獲隊長。這是歸屬提示，不把「同場」當成「同回合」。

diagonal 已納入本批源碼，預設 false。它讓手指路徑走相鄰八格；消除、T／十字／四連仍只按橫直規則。預覽、評估、執行逐步確認、刺珠與設定保存採用同次政策，變更設定使舊預覽作廢。方向增加可能縮短路徑或減少接觸，也可能在固定預算內擴大搜尋成本；目前沒有新版效能結果。

源碼與回歸案例尚未編譯或執行，沒有新 dylib 交付。依本批安排，使用者明確說「編譯測試」後才跑 suites、建置、模擬器檢查及打包。真機還需確認直接斜格交換、兩端 token、30／60 fps、停止及放開；原生 fixture 只檢查座標送入及 input lease，不能代替遊戲實際交換。待驗證清單見 [開發記錄](development.md)。

## 多人只轉珠的建議

只透過原生手勢轉珠、由遊戲同步結果，值得作獨立後續研究。至少需核對本機是否為目前回合擁有者、盤面與輸入 manager 是否仍屬同場，以及輪替、超時、離線和放開時的處理；需要雙端裝置與同步結果支持。

目前有多人狀態差異和斷線回報，尚未證明現行自動輸入能安全沿用。建議先驗證單人窗口與 diagonal，再研究多人自動轉珠；本批仍全部限單人，未加入多人開關。套隊、技能、計時、HP／充能等其他戰鬥功能保留限制。既有同步證據見 [多人限制](three-player-entry.md)。
