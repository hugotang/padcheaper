# 形狀目標與隊長盤面條件

`0.5.1-orbs` 的形狀與隊長盤面功能。編譯及自動測試結果見 [驗證記錄](development.md)；新增功能仍需真機核對。

2026-10-31 新源碼加入 3／4／8 人本機隊長／助人解析，**0.5.13 已在 [CI 86](https://github.com/hugotang/padcheaper/actions/runs/41183970392) 通過編譯及自動回歸，結果見開發紀錄；0.5.12 不含此擴充**。多人操作仍限明確點擊「轉一次」；原生來源、4 人額外技能助人及固定隊伍版本的處理見 [多人隊長盤面](orb-multiplayer-once.md)。

0.5.13 的 4 人回報後，本批源碼再修正固定版本資料上界、補充 113 個專用隊長技的原始參數，並新增精確顆數目標。**尚未編譯或執行新案例，既有 0.5.13 不含這批修正。** 來源與待驗證見 [開發紀錄](development.md)。

0.5.3 的 [效果適配](orb-effects.md) 納入集中驗證，最新結果見開發紀錄：最少直線及相連消除門檻、不可消色都參與目標判斷；轉轉每個共用相位都必須達標，顯示最低達成數。邪魔等特殊珠只計基本 Combo，不供應六色目標；毒／猛毒及首批未消爆彈另有禁止執行條件。

0.5.3 的 [四連與複合形狀搜尋修正](orb-shape-search.md) 已通過桌面求解器回歸：四連改按實際消除群組，允許未消同色鄰珠；加入補珠／拆組／布局評估與候選分流。下表為目前原始碼語意，已交付 0.5.2 仍額外禁止四連旁的未消同色珠。

## 使用方式

自動轉珠頁提供「高 Combo／指定形狀／隊長盤面」。

- 高 Combo：按 Combo、消珠數與路徑長度排序；後續效果批次優先選擇不觸發毒／爆彈限制的路線。
- 指定形狀：在原生設定頁新增最多 6 項條件，選擇珠色、形狀／連消／多色／最低 Combo 及組數。全部條件都要成立。儲存成功才套用，失敗保留草稿與頁面，錯誤顯示在固定儲存按鈕上方。
- 隊長盤面：每次讀盤從目前戰鬥隊長及助人的角色資料帶入可辨識的最低盤面條件。切換回高 Combo 會保留先前手動設定；可把已解析的隊長條件帶進手動編輯頁調整。

例如資料中的羅半 `#14242` 對應木整直行；時間厳守のメイド・ミル `#13834` 對應心十字及五色攻擊珠四連。兩者一起規劃時，三項條件皆需成立。

預覽逐項顯示達成數。珠數明顯不足時不產生路徑；搜尋預算內只找到部分條件時，保留可重播的路徑並標示未達成，停用執行。0.5.3 另在訊息及停止記錄列出缺少的條件、求路耗時、時間及步數上限。求路有時間與步數上限，未找到完整路徑不能當作不存在解的證明。

## 判定範圍

| 條件 | 判定 |
|---|---|
| L／十字／T | 首批消除的獨立 5 顆；L、T 包含四個旋轉 |
| 3×3 | 首批消除的獨立 9 顆正方形；3×4 不符合 |
| 四連 | 首批消除的獨立直線 4 顆；2×2 與五連不符合 |
| 整橫排／整直行 | 同一首批消除群組包含實際盤寬的一整行／盤高的一整列 |
| 連消 | 同一群組至少指定珠數，可包含盤內連鎖 |
| 精確顆數 `exact`（待建置） | 首批實際消除的一組恰好 N 顆，不限形狀；超過 N 顆或後續連鎖不計 |
| 多色 | 指定珠色集合中，實際被消除的不同顏色數，可包含盤內連鎖 |
| 最低 Combo | 本次消除及盤內連鎖的 Combo 合計 |

四連要求實際被標記消除的相連群組恰好為四顆直線，未消同色鄰珠可以保留；若鄰珠也被消除並接成五顆以上則不符合。L／T／十字／3×3 仍保留不得相鄰同色珠的保守規則，包括尚未成三連的鄰珠。形狀只計首批消除；Combo／多色／連消可計入目前珠子落下後產生的連鎖。全部評估均不含隨機天降或隊長追加 Combo。

單一條件要求多組時，必須分成不同消除群組。不同條件可由同一消除同時滿足，例如 5×4 的木整直行也可能是一組木四連。相同條件只保存一次，用組數表示需求；雙隊長重複要求相同條件時採較高門檻，避免無故要求消兩次。

## 隊長解析的界線

「隊長盤面」只提供盤面目標，**不是完整隊長技發動判定或傷害計算**。

- Combo、多色、連消、心十字、L 及部分覺醒發動條件，依技能 type／params 的已知結構轉換。
- 覺醒類條件可轉換四連、3×3、L、十字、T、屬性橫排／直行、三至五色及部分同色多串。它尚未判斷目前隊伍是否具備有效覺醒、是否被封鎖或實際攻擊屬性；消到某顏色不代表一定有隊員以該屬性攻擊。
- HP、技能使用、隊員組成與回復量條件會列出「未評估」。技能加算 Combo、重複發動倍率、屬性／類型倍率與傷害未計入求路分數。
- 毒／猛毒等未支援珠色、未知技能 type、未建模的選擇條件、精確 Combo、部分精確連消、無效參數與循環技能引用，會停用這次隊長規劃並提示改用手動設定。沒有丟掉未知條件後宣稱全部完成的回退。
- 解析採最低啟動門檻。達成盤面目標後才以 Combo 等既有分數排序，不追求隊長技的最高倍率。

初版 type 支援範圍：

| 盤面條件 | type |
|---|---|
| 最低 Combo | 66、98、103、104、166、169、223 |
| 不同顏色 | 61、165、170、194、199 |
| 最少連消珠數 | 109、119、159、167、182、200、219；235 的最少連消或精確四連分支 |
| 指定顏色多串 | 124、164、171、201、206；限可無歧義轉成同色組數或全部指定顏色的條件 |
| 十字／L／心四連 | 151、157、209、210／193、220、221／149 |
| 部分覺醒盤面條件 | 271、280、285 |
| 複合技能 | 138，遞迴深度及子項數有上限 |

## 資料與當前角色

離線索引 `ios/data/leader-orbs.json` 由 public `mon_ja.json`／`skill_ja.json` 的角色與技能參數產生，包含 14,229 筆角色、7,724 筆隊長技索引；這些筆數不代表全部隊長技均受支援。來源是 [PADDashFormation](https://github.com/Mapaler/PADDashFormation)，revision `b6c56dc1a67c3d72767e3d6a1ba3ffa373d2895f`。參數語意參考同 revision 的 [script-skill-parser.js](https://github.com/Mapaler/PADDashFormation/blob/b6c56dc1a67c3d72767e3d6a1ba3ffa373d2895f/script-skill-parser.js)。索引與編隊 catalog 使用相同 card／skill SHA-256；不執行上游腳本，也不按技能敘述文字猜測條件。

`update_leader_catalog.py` 只讀取下載的 JSON 並產生源碼資料。`generate_leaders.py` 在獲准建置時將索引內嵌進 dylib，手機不需要 Python 或網路查詢。執行期首次使用隊長盤面才解析索引。

本批另保存 `ios/data/fixed-leader-skills.json`：同 revision 原始 `monsters-info/official-API/ja-card.json` 的 117 筆固定角色引用及 325 筆技能參數，對應普通索引遺漏的 113 個隊長技能。名稱／ID 不替代實機身分校驗；合併只按實際技能 ID 查詢，不能覆蓋普通 profile。授權 generator 執行時驗證來源及完整依賴，再解析補入。固定專用 type 235 可產生精確長度，type 119 等連消及 193／220／221 的任意珠種 `1023` 採明示的六色子集，不使用毒／爆彈滿足條件；其他未知遮罩不會截斷後放行。未建模類型繼續停用。

原生快照讀取已核對的 visible member 位置 1／6，使用目前 `catalogID`、有效旗標及 catalog parameter pointer／record ID 比對，再轉成圖鑑號碼。單人保留既有索引方式。讀不到完整雙隊長時不沿用舊 ID；高 Combo／手動形狀仍可在普通盤面使用。保存的隊伍草稿不作為隊長來源。

本批多人源碼額外核對本機席位／顯示隊伍／descriptor、protected 來源位置、永久及暫時變身、原生參數記錄與該記錄的隊長技能 ID。普通圖鑑號碼只用於顯示；固定隊伍版本按實際技能查索引，未收錄或未支援就停用整組隊長規劃。已確認技能 ID 0 才是空條件。4 人額外技能助人需完整核對私有記錄、來源與 inactive 旗標，明列其不提供助人隊長技；不能把普通助人讀取失敗當成空條件。

隊長／助人變化會作廢舊預覽及 worker 結果；下次讀盤重新規劃。執行前及逐幀確認也比對角色 ID，多人另比對來源、原生技能、型態及參數身分。原生按下或交換完成後，先核對求路時的角色，再接受該步，避免把剛變更的隊長狀態接到舊路徑。多人座標轉換後再次核對；取消後僅可在同一有效窗口放開自己持有的珠子，跨場景／回合不送舊清理。

多人閒置面板及「用這些條件自訂」取目前 `liveLeaderPlan`。舊路徑／達標數不附在新條件上，搜尋與執行歷史則保留當時的 `leaderContext`。診斷顯示 native catalog／skill ID、來源位置、型態與額外助人辨識，沒有程序指標。證據與新增指紋見 [多人隊長研究](../research/orb-multiplayer-leaders-20261031.json)。

## 求路與設定

`PHOrbGoalSet` 是有界限的值型別，由背景 worker 隨盤面、品質及取消旗標一起擷取。後續效果批次先比較毒／爆彈條件，再優先保留完成全部目標的候選；形狀搜尋修正另使用補珠距離、干擾珠、組數與布局衝突引導未完成候選，並保留不同缺項及布局的名額。這些接近程度不會算成達成，也不會授權執行。求解完成後重播路徑並重新評分；只有完整通過目標、妨礙處理條件且時間足夠的預覽可執行。

範例設定：

```json
{
  "orbs": {
    "quality": "balanced",
    "mode": "manual",
    "goals": [
      {"kind": "column", "colors": 4, "count": 1, "length": 0},
      {"kind": "cross", "colors": 32, "count": 1, "length": 0}
    ]
  }
}
```

`mode` 為 `combo`／`manual`／`leaders`。`colors` 為火 1、水 2、木 4、光 8、暗 16、心 32 的集合；31 是五色攻擊珠，63 是任意基本珠。`length` 僅供 `match` 的最少連消珠數，其餘為 0。Combo 條件的 colors 為 0。數值需為整數，布林、重複目標、超出範圍及空白手動目標會被拒絕。

舊設定預設高 Combo。品質變更保留目標，模式變更保留手動草稿；寫檔成功後才發布設定。變更任一項就取消舊工作及預覽。執行中的原生拖珠不接受設定變更。

## 驗證範圍

自動測試涵蓋形狀旋轉／精確邊界／第 42 格／同色分組／錯色與衝突／不足珠數、獨立 Combo oracle、資料 type／params 解析與來源一致性、當前雙隊長讀取與變化、未達標禁止執行、設定保存與失敗保留，以及兩種視窗的原生 GUI probe。執行結果與桌面求路耗時見 [驗證記錄](development.md)。

2026-10-31 多人隊長擴充已在 0.5.13 的 [CI 86](https://github.com/hugotang/padcheaper/actions/runs/41183970392) 通過完整回歸，包含每種模式／席位、4 人額外助人、固定版本的實際技能、未知條件停用、交換／變身造成舊路徑失效，以及自訂複製目前條件。既有索引筆數不代表所有多人固定隊伍的技能都已支援。

真機仍須檢查求路品質與耗時、首次隊長資料解析的延遲、7×6 多目標預覽，以及各形狀與隊長條件的對照。`0.5.0` 的既有通過回報不涵蓋本批內容。
