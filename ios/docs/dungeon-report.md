# 全層關卡資料匯出

0.5.17 新增全層 JSON 匯出，供分析關卡敵人及 Auto 停止原因。[CI 94](https://github.com/hugotang/padcheaper/actions/runs/41301161254) 已通過原生讀取、歷史保留、檔案匯出及四份 GUI 分享／取消案例；詳細結果見 [開發紀錄](development.md)，真機仍待驗收。

1. 進入一般單人 dungeon，等盤面可轉珠。
2. 開啟轉珠詳細面板，按「收集全層資料」。這個動作只讀資料，不會開始轉珠或施放技能。
3. 停在穩定盤面，等顯示「已收集層數／總層數」及「全層行動定義已收集」。首層即可收集後續層，不必通關；每 0.75 秒最多取一層，技能及轉珠期間暫停。
4. 按「匯出關卡 JSON…」，在系統分享介面存到「檔案」，再提供該 JSON 即可。

0.5.18 可改按旁邊的「隊伍對比」，直接帶入已收集紀錄與目前編隊計算 HP／盾情境；攻略提示可用 JSON 更新，換 dungeon 不需重編。詳見 [關卡對比與攻略庫](team-dungeon.md)。

開始讀盤或 Auto 後也會收集。若 Auto 中途停住，直接匯出當場紀錄；後續手動通過仍可在離場後匯出。最近一場資料保留於記憶體，下一場、帳號切換或程式關閉會清除。取消分享只刪除暫存匯出檔，收集紀錄仍在。

## 檔案內容及範圍

- `floors`：這次入場已載入的全層敵人出現資料、catalog ID、等級及原始欄位。
- `floorDefinitions`：每層敵人的 64 列行動表、原始定義、複合子招及尚未解讀的 opcode；各層獨立標記是否收集完整。
- `observations`、`observedDefinitions`：實際觀察到的盤面、玩家／敵人 HP、異常、倒數及 AI 狀態，附來源層與原始定義識別。不是尚未到達樓層的實戰快照。
- `lastSearch`、`lastStopReason`：同一場的最近求路與停止診斷；沒有 Auto 紀錄時可能省略。

全層是「本次入場載入的所有樓層」，不包含其他入場可能抽到的隨機敵人。原始定義完整不代表已解讀所有分支、先制或下一招；`enemyForecastKnown`、`survivalKnown` 仍為 false。資料不足可先匯出，`allFloorsCaptured`、`allDefinitionsCaptured` 與逐層標記會保留缺口。

收集上限為 100 層、每層 8 個出現記錄、每層 192 個 referenced action、128 筆不同實戰狀態及 256 組實戰定義；舊狀態超限會移除並增加 `droppedRecords`。單檔上限 32 MiB，超限或儲存失敗會顯示失敗，不會假稱檔案已建立。匯出不含帳號認證、原生指標或一般 runtime 診斷，也不會自動傳送。

## 原生來源與測試界線

PAD 23.6.0 build 106878 的 count RVA `0x2a9d1dc` 與 spawn-table RVA `0x2a9d1e0`，每層 264 bytes、出現記錄 32 bytes。以目前敵人的精確 spawn 指標與 wave 綁定本次入場；資料雙讀、入場／帳號及末次盤面核對失敗時不發佈該頁。未來敵人的 catalog 會獨立查找並跟隨版本鏈，不借用目前敵人的定義。

新增九組獨立指紋並沿用行動表來源驗證；這組失配不阻止原有讀盤。連續模式、技能與戰鬥修改仍只限一般單人；3／4／8 人及 3 人單人續玩不收集全層。測例涵蓋跨層、版本鏈、缺定義、競態、離場保留、帳號清除、實際檔案與取消分享；具體已執行結果見 [開發紀錄](development.md)，真機資料仍需實際匯出確認。
