# 0.3.2-battle：phase 2 輸入判斷修正

2026-10-27；日服 iOS PAD 23.6.0／106878。使用者回報「尚未替換隊員－等待玩家操作階段（phase 2）」。舊版把非操作階段與非空閒輸入合併為同一原因，且輸入來源位址錯誤。本版修正原生讀取與提示；實際換怪仍待真機驗證。

## 根因與原生證據

`0x1005B6488` 在 `GameMain+92` 寫入 `33882371`（`0x02050103`，四個 bytes 為 `03 01 05 02`）。舊版要求其中前兩個 bytes 必須為零，將遊戲既有的初始資料誤當成觸控活動。`0x10060D1F0` 雖然也讀取 `GameMain+93`，真正判斷手指按下／持續觸碰的位置卻是 `0x100069C68()` 傳回的觸控記錄 `+213/+214`。

IDA 9.4 已核對的觸控流程如下。所有 VA 均屬原始 executable UUID `DD332AD4-4C92-3AAF-85D0-3892556A3A0E`，SHA-256 `611c93f5472fceddfa27254b718c6eff1decdc6814cc927e2faa4c7c250a65ec`。

| 原生函式 | 已核對行為 |
|---|---|
| `0x10006A224` | 配置 2672 bytes，指標存於 `H+0x2AC6FD8`；清空兩組各五個觸控記錄 |
| `0x100068DF0` | touchesBegan：原始記錄 `+248` 保存 UITouch；`+213..216` 設為 `01 01 00 01` |
| `0x10006935C` | touchesMoved：更新相同原始記錄的位置及狀態 |
| `0x1000693E4`／`0x1000694D0`／`0x100069554` | 放開／取消：清除原始 UITouch，`+213..216` 設為 `00 00 01 00`；極短按可能留下 `+220` 待處理事件 |
| `0x100069CAC` | 每幀把原始記錄整理成遊戲輸入；清除當幀 began/end/repeat，持續觸碰與放開分支另外更新 held 與 `+219` 追蹤旗標 |
| `0x100069C68` | 從 `manager+1320` 的當幀記錄選取觸控；使用 `+213`，不是 `GameMain+93` |
| `0x10060D1F0` | 玩家操作處理；拖珠期間 `battleImpl+624824`（`0x988B8`）非零，結束後清零 |

UIKit 的 `IS_MTK_VIEW touchesBegan:/touchesMoved:/touchesEnded:` 分別在 `0x1003A4A2C`、`0x1003A4B64`、`0x1003A4C9C` 呼叫上述處理函式。`drawFrame → 0x1004EC5F0 → 0x100069CAC` 先整理觸控，再執行遊戲更新。隊員替換維持在原始 drawFrame 返回後執行；計時檢查維持在原方法前及背景恢復後執行，因此兩者都讀取原始與當幀兩組記錄。

## 新判斷

每筆觸控記錄長 264 bytes；原始組從 manager 開始，當幀組從 `+1320` 開始。兩組都檢查五個位置，不能只相信 `+2640/+2641` 的事件數量或只檢查第一根手指。

- 原始 began／held、尚存在的 UITouch、`+220` 待處理短按：等待。
- 當幀 began／held／ended／repeat 或 `+219` 追蹤旗標：等待。
- 已被遊戲處理的原始 ended 可繼續保留；它本身不阻擋下一次操作。
- 仍在拖珠、輸入指標改變、資料不可讀或記錄不合法：不進行替換。
- 仍要求 phase 2、分類 0／1、source 0、multi 0，以及帳號／戰鬥身分、保護值、HP／隊員摘要與原生函式校驗。

此修正只讀取觸控資料，不清除遊戲旗標、不修改 phase，也不攔截或偽造觸控。

## 診斷與測試

面板分別顯示「等待玩家操作階段」、「等待放開觸控或輸入處理完成」、「等待本次拖珠結束」或「觸控狀態未通過檢查」。`status.json` 的 `battleState/timerState` 和「複製診斷」包含讀取是否有效、事件數量、活動位置 mask、原始及當幀 event bytes；戰鬥另有 `dragActive`。診斷不輸出觸控物件指標或座標。

`rawInputFlags/frameInputFlags` 是五個位置的 event bytes 按位 OR，從低到高依次為 began／held／ended／repeat。例如 `0x00010000` 表示 ended；它在 raw 組可長期保留，在 frame 組則會等待消費完畢。mask 的 bit 0–4 對應各觸控位置。

回歸測試涵蓋五個觸控位置、按下／持續／放開／短按／抑制事件、保留的 ended、非零事件數量、錯誤位址、指標更換、不可讀資料、phase 2 的等待提示，以及輸入消費後排隊套用／還原。輸入仍未知時，手動計時撤窗保持停用；原有自動計時旗標策略保持不變。

這些檢查不能替代真機驗收。更新後在同一單人關卡停止拖珠並放開手指，待面板顯示可替換，再測試單名套用與還原；若仍被阻擋，複製新診斷可定位下一項原因。
