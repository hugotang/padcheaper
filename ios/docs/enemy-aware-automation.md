# 敵方行動預判與技能保留設計

2026-10-31。狀態：設計完成，未接入執行路徑，未驗證敵人 AI／傷害結算。先以雨龍 × 白哉隊作驗收隊伍，功能範圍為一般單人自動。多人及 3 人斷線後的單人續玩仍沿用明確「轉一次」。

目標是減少有依據可避免的自動中斷，同時避免為了防止武裝蓄滿而提前花掉下一個必需的解覺醒／不可消技能。入場自動解析已載入的關卡資料；每次技能、盤面結算、敵人行動及換層後，用新的實際狀態重新決策。

## 一、敵方資料與行動分支

先拆開兩類資料：不隨本回合變動的「行動定義」，以及本次入場／這隻敵人的「執行狀態」。優先從遊戲已載入的原生資料唯讀取得；攻略只作對照，不能僅憑相同角色編號套另一個難度或活動的行動。

行動定義須保存原始 ID、原始參數、資料版本／雜湊及解析器版本。首批支援普通攻擊、固定連擊、覺醒無效、指定珠色不可消、技能延遲、蓄能與倒數；其餘以明確未知節點保留。若技能與傷害綁在同一次行動，必須保留先後次序。之後逐項加入 HP 門檻、憤怒、一次性行動、根性／超根性、敵人部位、特殊計數器及複合控制流程。

每個敵人以入場識別、spawn 世代及原生身分定位，不能只用盤面位置／角色號。狀態至少包括 HP／最大 HP、有效攻擊修正、行動倒數、已執行回合、一次性旗標、當前 debuff、AI 記憶及其他敵人的存活狀態。全部欄位需經有界讀取、版本／UUID／程式指紋及前後一致性核對。不能為觀察而呼叫敵方選招器、消耗亂數、推進回合或執行任何行動。

輸出是「下一次敵方行動的可達分支集合」，包含每個分支的條件、順序、傷害及效果，並分為：

| 狀態 | 意義 | 對自動的用途 |
| --- | --- | --- |
| `complete` | 所有可達分支已解析，所需狀態已確認 | 可供存活及技能排程判斷 |
| `bounded` | 精確招式未定，但所有可達分支都有可證明的傷害／效果界限 | 使用最壞界限；保留造成風險的分支 |
| `unknown` | 缺少影響結論的參數、條件、資料或未支援指令 | 顯示缺口；不能據此放寬原停止條件 |

機率不作存活授權依據。即使只有小機率必殺，只要是可達分支就須考慮。反之，不把互斥招式直接相加；多敵人則依原生行動順序組合。路徑可能把敵人打進低血行動，所以分支以我方行動「之後」的敵方 HP 區間計算；尚未支援傷害預測時，保守保留所有可能的低血／存活分支，不假定能擊殺。

入場若只拿到目前樓層，未來樓層標為未知；隨生成補讀。未確認下一層先制前，不能把「本層能撐住」延伸成「現在打死就安全」。

## 二、用候選行動判斷存活

對每個候選「技能序列＋轉珠路徑」，先重播盤面，再模擬我方結算、敵方行動及必要的下一層先制。每個技能／敵人效果依其已驗證次序逐步更新狀態，不以一個總傷害數取代多段事件。

輸入使用目前受保護的 HP、有效最大 HP、綁定／覺醒／潛覺有效性、隊長條件、護盾及回血效果的持續時間、不可消、技能封鎖、盤面與當前技能形態。封覺醒後重新取得當下有效值；不沿用封覺醒前的全隊 HP、心珠強化／四消回血或屬性抗性。解覺醒不預設會補滿新增的最大 HP。

核對重點如下：

- 拖珠期間先承受荊棘，不能預支放手後的回血。
- 根據實際可消心珠、Combo、弱化、回復倍率及有效覺醒計算回血下界。不能只看到心四消就當作回滿。
- 毒／猛毒及持續回血按原生時序處理；未驗證回血與毒的先後時，不能用兩者淨額保證存活。
- 隊長減傷需證明這條路徑在每個轉轉相位均滿足條件；受 HP／技能次數／綁定等影響的部分另行確認。
- 現有護盾只在敵人攻擊時仍有效才計入。多段連擊、比例傷害後追加普通攻擊、憤怒後攻擊要逐段計算與取整。
- 技能延遲、再封技、重掛異常或改盤可能使下一回合救援失效，須同時更新後續可用動作。

每條完整可達事件序列中，HP 的保守下界在所有致死結算點都必須大於零，並保留策略指定的餘量。餘量只能加嚴已知界限，不能補救未知機制。簡單單次普通攻擊可顯示「可保證承受／最壞傷害／剩餘 HP 下界」，複合招式則顯示導致最低 HP 的事件序列。

只活過下一擊也未必足夠。如果下一回合仍無法解禁消或開盾，應前瞻到下一個可確認的救援時間；每次最多放行一個回合，重新讀實際結果。初版只放行有完整證據的單回合延後，較長的蓄技串仍待短期排程支援。

## 三、讓必要救援有條件延後

既有 `required` 的含義保持。新增獨立的救援政策，預設 `immediate`，只在策略明示 `defer-if-proven` 時考慮延後。供珠／變身／必需開場等不是救援條件，不能被延後判定順便略過。

| 狀態 | 建議行為 |
| --- | --- |
| 救援技能可用，現在施放符合後續需求 | 按原生技能流程施放，確認完成後重算 |
| 救援不可用，但一個防守回合及下一次救援已被完整證明可行 | 使用已聲明的防守目標轉一回合，保留自動意圖，下一回合重算 |
| HP 可活，但禁消光使隊長減傷無法發動 | 只有另有已確認的盾／防守方案才可放行 |
| 需要靠天降、未確認回血或「應該能打死」才會活 | 不授權該路徑，保留具體原因 |
| 所需資料未知或所有候選有致死分支 | 停止自動，顯示缺口／危險行動，等明確重新開始 |

延後是獨立的「蓄技／防守回合」，不是把原本光 T＋心四連結果偷偷算成成功。策略可聲明防守時最低消心、必要減傷顏色、是否允許擊殺及最多延後回合。若沒有這種策略，原目標不放寬。既有總開關、停止、前景、手指介入及原生輸入限制一律保留。

## 四、本體／武裝蓄能排程

雨龍隊的解覺醒位應被標成能力資源，例如「解除覺醒無效」「解除光／心不可消」，而不只是某個位置每 N 回合放一次。能力需綁定實際當前形態、技能 ID、解除回合數及效果副作用。

對每個資源追蹤本體 CD `B`、武裝蓄滿所需總 CD `T`、目前充能 `C`、技能階段與原生可選來源。在沒有原生二選一的普通情況，本體可用區間是 `B <= C < T`。同進化鏈在遊戲允許二選一時，武裝蓄滿可能仍可用本體；現有程式已支援施放時核對，不能一律要求預先花技。武裝本身若能解除同一事件且副作用可接受，亦可列為候選。

每個威脅轉為「最早／最遲可能需要這個能力的操作窗口」。封覺醒已發生時截止時間是現在；下層先制封覺醒後通常是下一個我方操作窗口；若先制本身會致死，盾或 HP 的截止時間則在進層之前。不能把這兩個時間混在一起。

普通情況下，預放技能後需在所有可達截止時間都滿足：本體重新蓄好，而且尚未被不可選本體的武裝蓋過。充能推進按已確認轉珠回合及每個 haste／delay 事件逐步計算，不用真實秒數、按鍵次數或「大概幾層」。計入施放本體可能改變技能階段、同回合其他技能加速、敵人延遲、延遲抗性是否有效及武裝消耗。完成回報／目前 charge 永遠優先於預測；不寫入 charge 或調整原生計時。

以下只示範算式，並非雨龍隊實際技能數值；假設本體 CD 5、總 CD 18、目前 17，施放後歸零，每個完整轉珠回合加一，沒有其他加減速：

| 下次救援可能時間 | 預放後到時充能 | 判斷 |
| --- | --- | --- |
| 6–7 個充能回合後 | 6–7 | 落在 5–17，可列為預放候選 |
| 2–3 個充能回合後 | 2–3 | 本體未回來，不能只為防跳武裝而花掉 |
| 2–7 回合的隨機分支 | 2–7 | 需覆蓋最早的 2 回合；不能用平均時間授權 |
| 未知下層／分支 | 未知 | 提示武裝風險；不自動假定有足夠重蓄時間 |

排程同時比較「現在用」「稍後用」「保留本體」「允許武裝／原生二選一」「替代救援」「安全蓄技」。既不把 C 接近 T 當作必須使用，也不只看最早截止時間：很晚才發生的分支亦可能再次蓄滿武裝。若本體滿但 native 不允許在無異常時空放，就不能安排該預放。副作用包括改盤、吃掉必要光／心、覆蓋護盾／回復、血量變動、變身與開啟加速；每一項都影響候選可行性。

## 五、由機制產生臨時轉珠目標

2026-10-31 追加需求：遇到武裝無效時，能自動排出光 L 等有效的解除形狀。這層可先依目前異常運作，不必等到完整敵人 AI 解析完成；預判之後可進一步為下一個必需 L 保留對應珠色。

建立「解法能力表」，把主動技能、覺醒／潛覺、已生效盾／回血和轉珠解法放在同一候選系統。每個能力包含提供者、當前屬性／形態、有效前提、觸發形狀、效果強度／回合數、實際生效時點及失效原因。資料來自當前戰鬥的實際配置與狀態；匯入模板只是預期配置，不能當成已裝上或仍有效的證據。

| 當前機制 | 候選解法 | 必須先確認 |
| --- | --- | --- |
| 暫時武裝無效 | 有效的武裝無效回復潛覺＋符合提供者屬性的 L 消 | 潛覺、有效 L 覺醒、當前屬性、綁定／覺醒限制、剩餘回合及實際回復量 |
| 光／心不可消 | 解禁消主動，或已核對的不可消回復潛覺與對應消法 | 所需珠色能消、提供者有效、解除量／時點；不能靠被禁止的珠色觸發 |
| 根性 | 隊長固定追打，或有效追打覺醒的消心形狀 | 是否可保證觸發、傷害／無效／根性類型；超根性須另行建模 |
| 鎖珠／鎖珠掉落 | 已核對的解鎖主動，或有效 L 解鎖 | 首消後解鎖不能預先當成此刻轉色技能可轉掉的珠子 |
| 缺盾、回血或解異常 | 對應技能、已生效效果、可證明的轉珠機制 | 所有前提與發動順序，避免把看到形狀當成效果已完成 |

「武裝無效」「武裝被消耗／移除」「禁止 assist 的關卡規則」要分開；L 不會憑空還原已移除的裝備。潛覺的啟動條件、L 覺醒折算、同色／異色多個 L 的疊加與恢復時點要逐項按原生證據實作，此設計不先假設每個 L 一定回復固定回合。

雨龍基本模板的第 3 格卯之花烈 #14060 已配置武裝無效回復潛覺 ID 48，見 [模板來源](../templates/ishida-uryu-gamewith-574233/README.md)。實作時仍須讀出當前成員的有效潛覺、L 覺醒與屬性：若可用光 L，才加光 L；若另有合法屬性，評估較容易安排的選項。L 覺醒若只由正在失效的武裝提供，或當前封覺醒／綁定使所需條件失效，不得自行假設能觸發。若需要多個 L 才解除足夠回合，數量由已核對的效果模型決定。

臨時目標用依賴關係組合：先解除會阻止 L 生效的狀態，再求有效 L，觀察原生武裝無效剩餘回合變化，最後恢復通常策略。不以「求路顯示 L 達標」當成解除成功，也不預先把恢復的武裝屬性／覺醒／HP／RCV／技能 CD 計入更早的事件。特別是解除後可能立即改變武裝蓄滿／本體可用性，技能排程要一併更新。

一般目標分三個來源，診斷保留每個來源及必要原因：

1. **本回合存活與必要解除。** 例如可生效的武裝回復 L、當前仍有效的護盾條件及回血下界。
2. **本次戰鬥策略。** 例如雨龍光 T、心四連、避免打入某 HP 分支／特定層的擊殺要求。
3. **品質偏好。** 例如多 Combo、較短路徑及保珠。

預設把臨時 L 與原策略目標共同求解。光 T 與獨立光 L 至少需要 10 光，還要容納兩者邊界及心四連；目前 9 光技能門檻不是足夠的複合目標珠數。若盤面只有 7 光，就先比較補珠／其他有效 L 屬性／技能救援；不能直接塞三個形狀，等逾時後反覆重試。多種形狀／同色多組須用聯合布局與必要珠數檢查，避免同一群珠被當成不同精確形狀重複計數。已達 6 個目標上限時明確回報，不丟棄某個救援條件。

若無法同時達標，只能在策略明示的「機制處理回合」中，且有完整存活和下一回合救援證據時，暫時切換部分攻擊目標。被換掉的光 T 可能也是隊長減傷條件，不能僅因它列為通常策略就刪掉；依賴仍成立時必須保留。心四連若用來開放毒／猛毒，亦不得被 L 取代後仍沿用放毒許可。已經解除的臨時目標在重新讀取確認後撤下，不寫回／污染保存的 profile。

第一批驗收情境：武裝無效→有效光 L→回復回合數下降→解除後回復光 T＋心四連；無對應潛覺／只有武裝提供 L／施放者被綁／封覺醒／屬性被換→不得假報恢復；不同屬性 L 擇一、多 L、差一回合未解除；光不足以同時 T＋L、替代色可用、不可消重疊、5×4 空間不足、轉轉六相位皆須有效；解除後 HP／CD 變更、手指或技能介入／換層→撤銷舊目標與預測。以上仍是待寫及待驗證的案例。

### 雨龍隊：L＋心四連耐久，再回到輸出

使用者已明示偏好：減傷足以承受接下來敵方行動時，可先以有效 L＋首消心四連處理武裝無效並回復，下一回合再輸出。把它作為這份雨龍策略的明確分支，名為「修復耐久回合」，而不自動套到所有隊伍。它可暫停通常的光 T 輸出目標；但以下全部成立才授權一次轉珠：

- L 提供者與屬性、有效潛覺／覺醒已確認，能解除本次需要解除的武裝無效回合；若只能部分解除，需另有完整的後續計劃，不能預設下一回合已修好。
- 實際這條 L＋心四連路徑的減傷足夠，且在敵人每一段攻擊時仍有效。光 T 若是本回合隊長減傷的必要條件，就必須加回 T，或先取得可獨立承受的盾。畫面上仍顯示上一回合盾，不能當成這次不消 T 也會保留的證據。
- 心珠可消，所有共享轉轉相位均有首消精確心四連。以當下有效覺醒／回復倍率與原生結算時序計算回血下界；不能因武裝將在同一輪回復，就預先用恢復後的心珠強化算更早的回血。
- 全部存活敵人的可達行動序列、毒／猛毒、荊棘及可能換層先制都不致死。減傷後單段攻擊的數字並不足以覆蓋其後連擊、比例傷害或再封技。
- 預判下一個操作窗口仍有可行的動作：必需供珠、解覺醒／不可消、護盾及技能來源不會因蓄滿武裝／延遲而失效。下一回合輸出是預期結果，必須依實際新盤面重算，不能提前承諾必定可輸出。

狀態流程為「通常輸出 → 修復耐久候選 → 本回合存活核對 → 執行一次 → 觀察 L 回復量／HP／盾／charge → 重新求通常輸出」。此處「耐久」指防守目的，不保證零傷害；L 和其他消珠仍可能打死敵人或觸發低血／超根性分支。若不能界定我方傷害，就保留這些可能分支；不以「沒消 T」推定不會換層。

預設一次只授權一個耐久回合。效果仍殘留或下一回合情況不符時重新證明；超出策略允許延後回合、資料未知或沒有安全方案就停止，避免永久 L＋心四連卻沒有輸出。這個策略直接回答使用者的兩段安排，不能被高 Combo 排序改回當回合強攻。

新增驗收：固定有效盾足夠且無 T 仍可活→選 L＋心四連；盾需本回合 T／攻擊前到期→加回 T 或拒絕；心四連不能回復至安全下界→拒絕；單段能活但多敵人／連擊會死→拒絕；武裝無效成功解除→下回合恢復輸出；解除後武裝蓄滿／光不足／再次被禁消→重新計劃；意外擊殺／根性觸發→重讀敵人與先制；最多一次的延後預算與人工停止持續有效。

## 六、接入方式與有限前瞻

建議新增模組，以下是介面責任而非已實作檔案：

| 模組 | 輸入／輸出 |
| --- | --- |
| `PHEnemyCatalog` | 原始資料 → 有版本及支援範圍的行動圖 |
| `PHEnemySnapshot` | 穩定原生狀態 → 本次敵人身分、AI 狀態及完整性 |
| `PHEnemyForecast` | 行動圖＋我方候選結果 → 有序威脅分支及能力截止時間 |
| `PHMechanicGoals` | 當前異常＋有效覺醒／潛覺能力 → 帶來源、前提、解除量與時點的臨時形狀目標 |
| `PHSkillTimeline` | 技能形態／充能＋事件 → 可用窗口、預放／保留候選 |
| `PHSurvivalPlanner` | 路徑結算＋威脅 → HP 下界、可延後證據或具體拒絕原因 |
| `PHAutomationDecision` | 綜合結果 → 施放一技／求防守路徑／照常轉／等待穩定／停止 |

決策流程：穩定讀盤 → 解析目前威脅 → 執行必要救援／形成少量可用技能候選 → 求攻擊或防守路徑 → 逐候選核對全部相位、敵人分支與後續技能需求 → 選擇 → 最後重讀 → 執行一個動作 → 確認 → 全部重算。

排序為「當前及已知截止時間可生存、必要能力不缺席」優先，其次避免武裝蓋技、維持供珠／護盾循環、較少技能消耗，最後才比 Combo／傷害／速度。必要條件失敗不能靠加權總分抵銷。初版不要做完整關卡的大型搜尋；少量技能候選、有限回合與分支上限足夠。若超過預算，回報 `unknown`／保留原流程；不得截掉尚未探索的危險分支後回報安全。

行動定義按遊戲資料雜湊快取。動態結論按入場、樓層、spawn、敵人 AI／HP、隊伍形態／charge、玩家效果、盤面 generation 及策略版本失效。技能、復活、根性觸發、換層、死亡敵人、新生成部位、預測不符、手指介入、背景返回均重新取快照。遲到的 worker 結果不得恢復舊動作；人工停止不由新預測自動恢復。

## 七、顯示與紀錄

浮動列只顯示當下原因，例如「可承受下一輪，蓄技 1 回合」「解覺醒位 1 回合後蓄滿武裝，現在預放」「需要解禁消，但最快 2 回合、技能要 5 回合」「敵人低血分支未解析，已停止」。詳細頁可展開最壞招式、HP 下界、護盾條件、替代方案及救援截止時間。

`decisionTrace` 分開保存觀察值、推論範圍、支援缺口、候選被拒原因及最後原生確認；以新資料作真實結果對照。發現已解析的分支預測不符時，該資料版本／敵人模式撤回自動授權，其他有完整證據的資料不必一併停用。紀錄不含帳號資訊、指標或完整封包。

最新六格轉轉紀錄另有「缺光門檻跨相位」的規則停止。可在後續為可選供珠規則新增 `all-phases`／`any-phase-shortage` 語意：是否按最壞相位補珠須由策略明示，不能把所有 `Unknown` 一律變成略過。這與敵人傷害解析是獨立功能；預放及供珠都仍需原生可用與實際效果確認。

## 八、落地次序與驗收

2026-11-01 第一階段源碼進度：已接入 [目前戰況／解武裝 L 資格／充能的唯讀診斷](battle-observation.md)，尚未建置。它還不包含下列完整行動圖、下一擊傷害及存活授權；不把目前效果讀取當作敵人 AI 已解析。

1. **唯讀行動／充能面板。** 先確認敵方資料位置、格式、分支／回合語意與技能 CD 純讀途徑，補版本 guard。入場自動建索引，展示下一次可能行動及本體／武裝窗口，記錄預測與實際差異；不更改現有自動決策。
2. **武裝無效的有效 L 目標。** 先讀目前剩餘效果、實際潛覺／覺醒和屬性，按現況增加 L，保留既有必要目標並於解除確認後撤下。這一步不依賴未來敵方行動，不放寬現有停止條件；先用雨龍第 3 格驗收。
3. **雨龍隊的技能保留。** 策略明示解覺醒／禁消資源與預放許可；先對已確認行動、截止時間及可在無異常時使用的技能支援，否則只提示風險。另可使用明確樓層／事件保留作過渡；未知未來不能當成不需要救援。
4. **完整已知的一回合存活延後。** 普通攻擊／固定連擊、可驗證回血／盾／異常時序及下一次救援，先在單敵人的小範圍開啟 `defer-if-proven`。雨龍光禁消必須重算隊長減傷；不能僅因 HP 高就通過。
5. **擴展行動與多層排程。** HP 分支、隨機行動、多敵人、延遲／加速、根性、先制及較長蓄技串，逐項由原生證據與裝置比對擴大支援。

待寫／待執行的驗收包括：未知 opcode、錯誤／循環行動鏈、難度同號異表、一次性旗標、倒數及同名敵人替換；隨機致死分支與 HP 門檻；覺醒前後最大 HP、回血覺醒失效、盾消失、光／心禁消、毒加回血時序、多段及比例傷害；charge 在 B−1／B／T−1／T 邊界、同回合加速跨武裝、延遲、技能進化、同鏈選本體、原生拒絕空放；提早花技能反而錯過救援；新層／背景／停止／worker 競態；完整與未知資料都維持多人既有限制。

每條測例須有獨立預期事件序列、HP／charge 邊界與拒絕原因。先作唯讀回放，影子模式比較建議與實際觀察，再逐項允許改變單人自動；CI 不能代替裝置上原生 AI、技能和承傷時序驗收。本文件未宣稱以上案例已寫或已跑。
